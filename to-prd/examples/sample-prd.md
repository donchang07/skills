## 1. 개요

- **한 줄 정의:** 서비스 기사가 등록한 점검 결과를 AI가 분류·초안화하고 파트장이 확정하는 사내 회신 도구
- **해결하는 문제:** 점검 보고와 회신문 작성이 분산된 수작업이라 회신이 늦고 문구 품질이 들쭉날쭉하다
- **타깃 사용자:** 서비스 기사, 파트장
- **플랫폼:** 사내 웹(데스크톱·태블릿 브라우저)

## 2. 배경 & 근거

- **시장·경쟁 맥락:** 해당 없음 — 사내 업무 도구
- **차별 프레이밍:** AI는 초안만 만들고 확정·발송 판단은 파트장이 한다
- **기존 시스템 맥락:** 접수 건은 기존 CS 접수 시스템에서 일 1회 가져온다. 확정 회신문은 기존 고객센터 시스템에서 사람이 발송한다 [확정·출처: 업무 브리프 v1.5]

## 4. User Scenarios

### Scenario S1 — 점검 결과 등록과 확정

- **사용자:** 서비스 기사(노트북), 파트장(데스크톱)
- **상황:** 기사가 현장 점검을 마치고 사무실에서 결과를 등록한다
- **목표:** 당일 안에 확정 회신문을 만든다
- **흐름:** SCR-001 로그인 → SCR-002 요청 선택·결과 등록 → AI 분류·초안 표시 → 파트장 SCR-003 검토·확정
- **완료 조건:** Given 기사가 담당 요청을 선택함 When 점검 결과를 등록하고 파트장이 확정을 누름 Then 상태가 확정이 되고 확정자·확정 시각이 저장된다

### Scenario S2 — AI 판단 보류와 사람 확인

- **사용자:** 서비스 기사, 파트장
- **상황:** AI 확신도가 0.7 미만이거나 수리비가 10만 원을 넘는다
- **목표:** AI 결과를 그대로 쓰지 않고 파트장이 직접 판단한다
- **흐름:** SCR-002 등록 → AI 판단 보류 안내 → SCR-003 사람 확인 경고 → 파트장이 유형·회신문 직접 입력 후 확정
- **완료 조건:** Given 수리비 120,000원 건 When 파트장이 확인 체크 없이 확정을 누르려 함 Then 확정 버튼이 비활성이고 확인 문구가 보인다
