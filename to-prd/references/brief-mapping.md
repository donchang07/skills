# 업무 브리프 → PRD 대응 계약

> 브리프 버전: v1.2
> 템플릿: `assets/brief/PRD템플릿_v1.2.docx`
> 핸드북: `assets/brief/PRD작성핸드북_v1.2.docx`
> PRD 스키마: screen-first-v2

템플릿·핸드북·to-prd는 한 묶음이다. 어느 하나를 바꾸면 세 곳의 버전을 함께 올리고 `node scripts/check_sync.mjs`로 확인한다.

## 1. 읽기

1. Word 브리프는 `pandoc -t markdown <파일>`로 읽는다. pandoc이 없으면 `python-docx`로 문단과 표를 읽는다. 둘 다 안 되면 사용자에게 내용을 붙여 넣어 달라고 한다.
2. 브리프 파일 속성 제목(`to-prd 업무 브리프 템플릿 vX.Y`) 또는 파일명의 버전이 이 문서의 브리프 버전과 다르면 PRD 메타 `입력`에 차이를 기록하고, 아래 대응표에 없는 항목은 가장 가까운 장으로 옮긴다.

## 4. 모름과 추천값 적용

| 브리프 값 | 필수 항목 | 그 밖의 항목 |
|---|---|---|
| 내용 있음 | `[확정·출처: 업무 브리프 vX.Y]` | 같음 |
| 추천값 적용 | `[기본값]` + 13장 확인 요청 | `[기본값]` |
| 모름 또는 빈칸 | 객관식 질문 (5절) | `[기본값]`, P0 아키텍처가 달라지면 13장 결정 요청 |

필수 항목은 템플릿 상단 문구와 같다: **업무 문제, 사용자, 현재와 미래 흐름, 필요한 화면, 예외, 완료 기준과 반드시 통과해야 할 사용자 흐름**.

## 5. 필수 항목 객관식 질문

필수 항목이 비었거나 모름일 때만 묻는다. 한 번에 최대 4문항, 전체 2회 이내다. Claude Code에서는 AskUserQuestion을 쓰고, 그 도구가 없는 환경(Codex 등)에서는 같은 객관식을 번호 목록으로 묻는다. 첫 선택지를 `(추천)`으로 둔다. 선택지는 브리프의 업무 이름으로 구체화한다. 질문에 SCR·FR·SC·P0·Route·DATA·E2E·스택·PDCA를 쓰지 않는다.

| 필수 항목 | 질문 | 무응답 시 |
|---|---|---|
| 업무 문제 | 이 앱이 없애려는 불편은 무엇인가요? (브리프 맥락에서 2~4개) | 중단 — 업무 문제 없이는 PRD를 만들지 않음 |
| 사용자 | 이 앱은 누가 쓰나요? ① 팀원 + 관리 담당자 따로 (추천) ② 팀원만 ③ 나 혼자 ④ 외부 고객·협력사까지 | ① `[기본값]` + 13장 |
| 현재와 미래 흐름 | 앱을 쓴 뒤 일이 어떤 순서로 바뀌나요? (브리프에서 만든 흐름 후보 2~3개) | 첫 후보 `[기본값]` + 13장 |
| 필요한 화면 | 첫 버전에 꼭 있어야 하는 화면을 모두 고르세요. (복수 선택) | 흐름에서 도출 `[기본값]` + 13장 |
| 예외 | 자주 생기는 예외를 모두 고르세요. ① 반려·취소 ② 데이터 없음 ③ 외부 시스템 응답 없음 ④ 통신 끊김 (복수 선택) | ①② `[기본값]` + 13장 |
| 반드시 통과해야 할 사용자 흐름 | 이것만은 반드시 끝까지 되어야 하는 흐름은? (미래 흐름에서 만든 후보 2~3개, 복수 선택) | 미래 흐름 첫 후보를 `[E2E]` SC `[기본값]` + 13장 |
| 완료 기준 | 무엇이 되면 성공인가요? ① 처리 시간이 줄어든다 (추천) ② 빠뜨리는 건이 없어진다 ③ 입력 실수가 줄어든다 ④ 보고서를 따로 만들 필요가 없다 | ① + 목표값 `[가설]` + 13장 |

답변은 `[확정·출처: 현업 응답 YYYY-MM-DD]`로 반영하고 `docs/00-pm/_interview.md`에 `날짜 / 문항 / 선택 / 반영 위치 / 상태`로 기록한다. 업데이트 때 같은 질문을 다시 하지 않는다. 무인 실행이면 묻지 않고 무응답 열을 적용한다.

## 6. 비목표

- 템플릿 1장 "이번에 만들지 않을 것"의 각 항목이 NG-*가 된다. 9장 "나중에 추가할 것"은 비목표가 아니라 10장 이후 범위다.
- 다시 검토할 시점이 없으면 `[기본값] 다음 버전 기획 시`로 쓴다.
- 브리프에 비목표가 없으면 브리프에서 언급됐지만 MVP에서 뺀 기능을 `[기본값]` 비목표로 제안하고 13장에 확인 요청을 둔다.

## 7. AI 판정 계약

템플릿 7장 "사용할 AI 기능"이 `해당 없음`이 아니면 PRD 11.4를 채운다.

- AI 기능별로 입력, 출력, 사람이 확정하는 주체와 화면, AI가 틀렸을 때 되돌리는 방법, AI 실패 시 동작을 쓴다.
- 부록 A에서 AI 결과 필드와 사람 확정 필드를 다른 필드로 둔다. 확정자·확정 시각·AI와 다를 때의 사유 필드를 포함한다.
- 확정과 되돌리기는 FR로 만들고 `[E2E]` SC로 검증한다. AI 모델 응답은 테스트에서 모킹한다.
