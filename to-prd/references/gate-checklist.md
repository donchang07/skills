# bkit PRD 착수 게이트

목적은 “이 PRD만 받은 bkit이 화면·메뉴·권한·로그인·UI 요소·데이터를 추측하지 않고 Plan과 Design을 시작할 수 있는가”를 판정하는 것이다. **Hard Gate가 점수보다 우선한다.**

## 파일별 gate 경로

| 대상 | 통과/조건부 gate | draft gate |
|---|---|---|
| `docs/PRD.md` | `docs/00-pm/_product.gate.md` | `docs/00-pm/_product.gate.draft.md` |
| `docs/00-pm/{feature}.prd.md` | `docs/00-pm/{feature}.gate.md` | `docs/00-pm/{feature}.gate.draft.md` |

## 절대 규칙

1. 총평보다 결함을 먼저 쓴다.
2. 모든 결함은 장 번호, FR/SC/결정 ID 또는 표의 행을 인용한다.
3. PRD에 없는 사실을 만들지 않는다. 외부 확인이 필요하면 출처와 기준일을 요구한다.
4. 결함마다 `[작성자]` 또는 `[구현자]` 결정권자를 붙인다.
5. 정본과 파생본의 불일치는 파생본을 임의로 고치지 말고 정본에서 바로잡는다.
6. 점수가 높아도 Hard Gate 실패를 통과로 바꾸지 않는다.

## 1. 기계 검사

스킬 폴더를 기준으로 다음을 실행한다.

```bash
node scripts/validate_prd.mjs <PRD 파일> [추가 PRD 파일...]
```

검사 결과의 `ERROR`는 최소 Major다. 화면 계약 누락, ID 중복, 필수 장 누락, unresolved placeholder, 시스템 가정 행 누락은 아래 Hard Gate 규칙에 따라 Blocker가 될 수 있다. `WARN`은 사람이 맥락을 확인한다.

gate 파일에 명령, 종료 코드, ERROR/WARN 개수를 기록한다.

## 2. Hard Gate

다음 중 하나라도 실패하면 Blocker이며 착수 불가다.

| ID | 조건 |
|---|---|
| HG-01 | 정본의 모든 활성 `SCR/화면 요소/DATA/FR/SC` ID가 유일하고 상호 참조와 feature 분해표에 빠짐없이 연결된다. |
| HG-02 | 화면 인벤토리의 모든 `SCR-*`에 상세 블록이 있고, 역할·Route·진입/종료·레이아웃·UI 요소·전이·8개 상태·반응형·접근성이 정의된다. |
| HG-03 | 메뉴에 위치·순서·라벨·노출 역할·대상 화면·데스크톱/모바일 표현이 있고, 일반 사용자와 관리자 차이가 역할·레이아웃·요소 수준에서 드러난다. |
| HG-04 | 관리자 기능이나 보호 데이터가 있는데 `인증 사용: 예`와 독립된 로그인/인증 `SCR-*`, 실패·만료·접근 거부·로그아웃 처리가 없다. |
| HG-05 | 모든 P0 화면 동작 FR에 시나리오·`SCR-*`·요소 ID·`DATA-*`·SC·검증 방법이 연결된다. 적용되지 않는 열은 이유가 있다. |
| HG-06 | 저장·인증·권한·스택 등 P0 아키텍처를 바꾸는 `[결정 필요]` 항목에 안전한 fallback이 없다. |
| HG-07 | feature PRD가 정본과 같은 개정 버전을 가리키며 포함 화면·요소·FR·SC·데이터와 공통 메뉴·인증 계약이 정본과 일치한다. |
| HG-08 | bkit 버전·PRD 탐색 경로·실행 명령이 프로젝트의 로컬 계약 또는 `bkit-contract.md`와 일치한다. |
| HG-09 | 계약 섹션 4~8장에 실행을 멈추는 unresolved placeholder가 남아 있다. |
| HG-10 | 완료 판정에 match rate 기준, SC 통과, 화면 상태와 오류 처리 검증이 모두 포함된다. |

## 3. 숫자 재계산

합계·개수·기간·비율·금액·feature별 FR 수를 다시 계산한다. 맞는 값도 기록한다.

| 위치 | 문서 값 | 재계산 | 결과 |
|---|---:|---:|---|

불일치가 범위·비용·납기를 바꾸면 Major, 단순 표기면 Minor다.

## 4. 추적 연결표

| FR | 시나리오 | 화면·요소 | SC | 데이터 필드 | feature | 끊긴 칸 |
|---|---|---|---|---|---|---|

다음을 찾는다.

- 인벤토리·메뉴·상세 중 한 곳에만 존재하는 화면
- 시나리오 없는 FR
- 동작을 가지지만 FR이 없는 화면 요소
- 화면 FR인데 `SCR-*`·요소 ID가 없는 항목
- 측정할 수 없는 SC
- 화면 요소가 참조하지만 부록 A에 없는 데이터
- 읽기·쓰기 화면이 없는 데이터 필드
- 어느 feature에도 속하지 않는 활성 FR
- 어느 feature에도 속하지 않는 화면·데이터
- 정본에는 있지만 feature 파생본에 없거나 그 반대인 화면·요소·데이터·FR·SC

P0의 연결 단절은 Blocker, P1/P2는 영향에 따라 Major 또는 Minor다.

## 5. 화면 계약 완결성

`references/screen-definition-contract.md`와 5장을 대조한다.

1. 역할·접근 매트릭스에 비로그인·일반 사용자·관리자가 모두 있고 차이·제약이 구체적인가?
2. 인벤토리, 메뉴, 화면 상세의 `SCR-*` 참조가 모두 존재하는가?
3. 헤더·사이드바·하단 탭·프로필·관리자 메뉴의 위치와 순서가 데스크톱·모바일별로 명확한가?
4. 관리자·보호 기능이 있으면 로그인 화면과 성공 복귀, 실패·만료·권한 없음·로그아웃이 정의됐는가?
5. 각 화면의 모든 영역과 UI 요소에 실제 표시값, 권한, 조건, 데이터, 입력 규칙, 행동 결과가 있는가?
6. 각 화면에 초기·로딩·빈·성공·검증 오류·시스템 오류·권한 없음·오프라인 상태가 있는가?
7. 일반 사용자와 관리자의 레이아웃·요소·행동 차이가 명시됐는가?
8. 각 동적 요소의 `DATA-*`가 부록 A 필드와 연결되고, 쓰기 작업은 FR·오류·로그 계약을 가지는가?

P0 화면이나 인증 계약의 누락은 Blocker다. P1/P2 화면의 상세 누락은 영향에 따라 Major 또는 Blocker다.

## 6. 검증 가능성

FR과 SC를 한 줄씩 판정한다.

| 위치 | 판정 가능 여부 | 문제 | 수정안 |
|---|:---:|---|---|

다음이면 판정 불가다.

- 주체·조건·결과 중 하나가 없다.
- 성공과 실패를 나눌 기준이 없다.
- 외부 성과를 소프트웨어가 직접 보장한다고 썼다.
- 데이터나 환경 없이 수치만 있다.

P0 FR 또는 핵심 SC의 판정 불가는 Major이며, 무엇을 만들지 달라지면 Blocker다.

## 7. unresolved 표현 검사

단순한 일반 단어 검색으로 결함을 만들지 않는다. `가능`, `등`, `고려`, `추정`은 금지어가 아니다.

4~8장의 계약 값에서 다음 의미가 남았는지 확인한다.

- `TBD`, `TODO`, `미정`, `택일`, `검토 중`, `결정 필요`
- 채워지지 않은 `{placeholder}` 또는 `<placeholder>`
- “A 또는 B”처럼 bkit이 선택해야 하는 미확정 선택지
- “적절히”, “필요시”, “가능하면”처럼 판정 기준을 숨기는 표현

12·13장의 이슈/결정 표, 인용된 원문, 상태 라벨은 검사 대상에서 제외한다. 계약 섹션에는 확정값 또는 명시적 fallback을 쓰고 논점은 12·13장으로 이동한다.

## 8. 시스템 가정 10칸

11.2의 1~10번 행이 모두 있어야 한다. 각 행은 결정, 상태, 근거를 가진다.

- `[확정]`: 출처 또는 사용자 결정이 있다.
- `[기본값]`: 왜 안전한지와 재확인 시점이 있다.
- `[해당 없음]`: 적용되지 않는 이유가 있다.
- `[결정 필요]`: 13장 ID와 fallback 또는 중단 조건이 연결된다.

빈 행은 Major다. P0 설계가 달라지는 행에 fallback이 없으면 HG-03 Blocker다.

## 10. 외부 사실

부록 B가 가격·일정·법규·API·외부 서비스 사양을 담았는지 확인한다.

- `[확정·출처]`인데 출처가 없으면 Minor
- 그 사실이 P0 FR의 동작을 바꾸면 Major
- 재확인 시점이 지났고 P0 구현을 바꾸면 Blocker

## 11. 심각도와 점수

- **Blocker −20:** 그대로 시작하면 다른 제품·아키텍처를 만들거나 bkit이 PRD를 찾지 못한다.
- **Major −5:** 만들 수는 있지만 재작업·임의 결정·핵심 검증 누락이 생긴다.
- **Minor −1:** 의미를 바꾸지 않는 참조·표기·가독성 문제다.

100점에서 감점하되 결함을 인위적으로 합치거나 쪼개 점수를 조정하지 않는다.

- 착수 가능: Blocker 0, 90점 이상
- 조건부 착수: Blocker 0, 70~89점
- 착수 불가: Blocker 1 이상 또는 70점 미만

## 12. 다시 읽기

기계 검사와 표를 잠시 내려놓고 PRD를 처음부터 다시 읽는다. 다음 질문에 답한다.

1. bkit이 잘못된 기본값을 선택할 지점이 있는가?
2. 화면을 보지 않고 작성한 것처럼 보이는 FR이나 데이터가 있는가?
3. 메뉴·일반/관리자·로그인·화면 요소 중 구현자가 임의로 정해야 하는 부분이 있는가?
4. 정본에서 feature 파생본으로 내려오며 화면 계약의 의미가 사라졌는가?
5. 완료했다고 주장해도 실제로 검증할 수 없는 항목이 있는가?
