# 장동인 프레젠테이션 제작 스킬 · v3.0.0

## 적용 범위와 우선순위

이 스킬은 PPTX 제작·수정에 적용합니다. 웹·앱·DOCX의 디자인을 자동으로 바꾸지 않습니다.

우선순위는 사용자의 최신 명시적 지시, 최신 승인 템플릿의 고정 요소, `brand.json`, 이 문서와 `DESIGN.md`, 참조 예제 순서입니다. 문서 간 규칙을 섞어 적용하지 않습니다. `references/legacy`는 이력이며 현재 규칙이 아닙니다.

현재 기준 템플릿은 2026-09-15에 사용자가 제공한 `template(6).pptx`를 바이트 변경 없이 저장한 `template.pptx`입니다. 저장소의 이전 템플릿과 이미지 자산은 같지만 40개 내부 구성요소가 달라 첨부본을 채택했습니다. 비교·해시·좌표는 `references/template_manifest.json`에 기록합니다.

## 반드시 지킬 것

1. `template.pptx`에서 시작합니다. 표지·프로필·마지막 장은 시각적으로 보존합니다. 표지는 제목 문구만 바꾸며 원래 글꼴 크기·상자·위치를 유지합니다. 3페이지는 고정 페이지가 아닙니다.
2. 콘텐츠 제목은 Pretendard 24pt Bold, 가운데 정렬입니다. 제목에 단계 번호를 자동으로 붙이지 않습니다. 표지·고정 페이지의 원래 제목 크기를 24pt로 덮어쓰지 않습니다.
3. 박스 중제목은 16pt Bold 한 줄, 본문은 14pt Regular입니다. 표 헤더는 16pt Bold, 표 본문은 14pt Regular입니다. 캡션만 11pt를 허용하며 본문을 캡션으로 위장해 줄이지 않습니다.
4. 새 텍스트는 한글·영문·숫자 모두 Pretendard입니다. Regular/Bold만 사용하고, 한글·영문·복합문자 글꼴 매핑을 함께 설정합니다. 기호용 글꼴은 무조건 치환하지 않습니다. 글꼴이 없으면 중지하고 사실을 알립니다.
5. 텍스트를 담는 새 박스는 모서리가 직각인 사각형입니다. Square는 정사각형 비율을 뜻하지 않습니다. 원형·마름모·원통은 의미가 필요한 다이어그램 도형에만 사용하며 설명 카드를 둥글게 만들지 않습니다.
6. 박스 폭은 중제목 한 줄과 본문 읽기 폭을 확보하고, 높이는 실제 줄 수와 여백에 맞춥니다. 글자 자동축소를 하지 않습니다. 박스가 많으면 두 줄로 재배치합니다.
7. 원본의 왼쪽 굵은 네이비 선, 안쪽 짧은 수직선, 제목/본문 구분선, 그 밖의 장식은 실제 템플릿 도형에서 복사합니다. 문서의 근사 좌표로 새로 그리지 않습니다.
8. 반복 푸터 문구를 넣지 않습니다. 페이지 번호는 원본의 위치·색상·내부 여백과 8pt 서식을 사용한 일반 도형의 자동 번호 필드입니다. 표지 번호도 원본 표시를 유지합니다. 본문 하단의 고유한 결론 문장은 푸터가 아닙니다.
9. 완성 파일에는 제목·본문·번호 placeholder를 하나도 남기지 않습니다. 슬라이드·레이아웃·마스터를 검사합니다. 원본 템플릿은 변경하지 않으며 출력본에서 필요한 시각·글자를 일반 도형으로 보존한 뒤 placeholder 속성을 제거합니다. 단순 삭제로 원래 내용을 없애지 않습니다.
10. 전체 본문을 기계적으로 중앙 이동하지 않습니다. 프레임·제목·번호는 고정하고, 본문은 허용 영역에서 읽는 순서와 정렬선을 기준으로 배치합니다. 나란한 두 표를 각각 화면 중앙으로 이동시키지 않습니다.
11. 모든 장을 박스 나열로 만들지 않습니다. 내용에 맞는 비교표·업무 흐름·관계도·아키텍처·순환도·차트·화면 예시·아이콘 설명·불릿을 선택합니다.
12. 문장을 짧게 만들기 위해 개념이나 사용자 핵심 주장을 삭제하지 않습니다. 처음 나오는 용어는 그 자리에서 정의합니다. 결론을 제목에서 바로 말하고, 부드러운 서술형을 사용합니다.

## 내용 설계

각 슬라이드에서 전달할 주장, 필요한 정의, 근거/예제, 적절한 시각 형식을 먼저 정합니다. 질문만 던지는 장과 답하는 장을 불필요하게 나누지 않습니다. 목차·섹션 구분·요약 장은 도움이 될 때만 넣습니다.

한 장의 주제는 하나로 유지하되 비교표의 여러 항목처럼 그 주제를 설명하는 정보는 함께 담습니다. 모든 장에 큰 구호 하나만 넣지 않습니다. 역할·책임·실행 원칙은 불릿만으로 전달할 수 있습니다.

기존 방식과 새 방식을 비교할 때 기존 방식의 역량을 일부러 축소하지 않습니다. 사실, 사용자 제안, 가정 예제, 아직 검증하지 않은 효과를 구분합니다. 가상 수치는 차트 바로 옆에 표시하고, 실제 효과처럼 제시하지 않습니다. 출처는 해당 자료와 연결하고 상세 설명은 발표자 노트에 둘 수 있습니다.

발표자는 본문에서 자신을 제3자로 부르지 않습니다. 대화에서는 장동인교수님으로 호칭하지만 슬라이드 본문에 장동인교수님이 제안한다는 표현을 반복하지 않습니다.

## 시각 형식 선택

| 내용 | 우선 표현 |
|---|---|
| 같은 기준으로 두 방식을 비교 | 비교표 |
| 담당 주체와 실행 순서 | 조직별 행을 나눈 업무 흐름도 |
| 대상 사이의 연결 | 관계 이름이 있는 관계도 |
| 시스템 구성과 공통 통제 | 계층형 아키텍처와 연결선 |
| 버전별 기능 발전 | 단계형 도표/로드맵 |
| 기록 항목과 연결 | 항목 표 + 고유번호 연결 |
| 결과가 다음 입력이 됨 | 되돌아가는 연결이 있는 순환도 |
| 실제 측정값 | 단위와 출처가 있는 차트 |
| 프로그램 사용 | 실제 화면 또는 명시된 화면 예시 + 설명 |
| 개념 여러 개의 소개 | 같은 크기의 아이콘 + 중제목 + 설명 |
| 역할·책임·원칙 | 불릿 |

선은 순서, 데이터 전달, 통제, 참조 중 무엇인지 표현해야 합니다. 아키텍처를 단순 업무 순서도로 바꾸지 않습니다. 도표를 장식용 이미지로 통째로 굳히지 말고 가능한 한 수정 가능한 PowerPoint 도형·표·차트로 만듭니다.

## 제작 도구

- `brand.json`: PPT 전용 글꼴·색상·간격·정책의 단일 기준입니다.
- `chang_presentation.py`: 템플릿 기반 생성, 글자 폭 측정, 직각 카드, 두 줄 그리드, 아이콘, 연결선, 불릿, 차트를 제공합니다.
- `brand_tables.py`: 각 표에 배정된 영역 안에서 열 폭과 행 높이를 내용에 맞춥니다. 병합 셀은 임의 변경하지 않습니다.
- `inspect_template.py`: 두 템플릿의 바이트/부품 차이와 원본 좌표를 확인합니다.
- `validate_presentation.py`: ZIP·XML·관계·placeholder·번호·글꼴·제목 줄바꿈·넘침·텍스트 겹침을 검사합니다.
- `render_preview.py`: LibreOffice로 PDF와 전 장 PNG, 전체 미리보기를 만들고 실제 사용한 렌더러를 기록합니다.
- `build_examples.py`: 내용과 형식이 다른 참조 슬라이드를 생성합니다. 이 장수와 순서를 새 교안에 강제하지 않습니다.
- `tests/test_brand.py`: 고정 페이지·템플릿·표·박스·글자·파일 무결성의 회귀 테스트입니다.

명령 사용과 환경 준비는 `README.md`, 상세 배치는 `DESIGN.md`, 검수 기준은 `references/QA.md`를 확인합니다.

## 필수 제작 순서

템플릿과 자료 확인 → 주장과 예제 정리 → 시각 형식 선택 → 고정 크기의 글자 폭/줄 수 측정 → 박스와 도표 배치 → 생성 → 정적 검사 → 전체 렌더링 → 각 장 육안 확인 → 수정 후 다시 검사합니다.

원본 슬라이드를 지우고 추가하여 슬라이드 파트 이름이 중복되지 않도록 합니다. 제공된 `Deck`은 새 슬라이드를 먼저 생성하고 마지막에 필요한 페이지를 재배열합니다. 파일은 임시 파일로 완성한 뒤 최종 경로로 교체합니다.

## 완료 판정

저장되었다는 것과 정상적으로 열리고 보인다는 것은 다릅니다. 경로 존재/해시, ZIP CRC, 내부 관계, 글자/도형, 전체 이미지 변환을 각각 확인합니다. 사용하지 않은 PowerPoint나 모바일 앱에서 검증했다고 말하지 않습니다. LibreOffice 검증은 그 이름으로 보고하며 실제 PowerPoint 최종 확인은 구분합니다.

검사 오류 또는 확인하지 못한 주요 항목을 숨긴 채 완료라고 보고하지 않습니다. 전달 파일은 짧은 영문 파일명으로 제공하고, 필요하면 동일 파일을 ZIP으로도 제공합니다. 폰트 파일은 결과물이나 저장소에 포함하지 않습니다.
