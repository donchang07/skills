## 1. 개요

- **한 줄 정의:** 컨설턴트가 고객사 임직원 다수에게 익명 설문을 받아 그 회사의 AX 추진 수준과 인식 격차, 해야 할 일을 보고서로 만드는 진단 웹 앱
- **해결하는 문제:** 추상적인 AX를 측정 가능한 12개 영역과 두 축으로 바꾸고, 단일 임원 응답 대신 카테고리별 다수 응답으로 조직을 진단한다
- **타깃 사용자:** AX 컨설턴트, 고객사 임직원(경영진·AX/IT·직원), 고객사 담당자(CAIO, AX 추진 담당)
- **플랫폼:** 반응형 웹(응답자는 모바일 우선, 관리자는 데스크톱 우선)

## 2. 배경 & 근거

- **시장·경쟁 맥락:** 글로벌 컨설팅사·벤더·표준·학술·한국·상용 도구 30여 개 진단 모델은 전략·데이터·기술·거버넌스·인재·문화의 6개 축과 4~5단계 구조로 수렴하지만, 거의 모두 기업당 임원 1명 응답이고 문항을 공개하지 않는다. 리더와 현업의 AI 인식·사용 격차는 여러 조사에서 반복 보고된다 [조사·2026-10-01] (reports/AX 성숙도 진단모델 비교.md, BCG AI at Work 2025·2026, Microsoft Work Trend Index 2025, Gallup).
- **차별 프레이밍:** ① 카테고리별 다수 응답 집계 ② 인식 격차를 결과물로 제시 ③ 점수에서 30/90/365일 과제로 직결. 저자 강의자료는 AI 프로젝트 실패 원인으로 "구성원 간 AI에 대한 생각이 모두 다르다"를 든다 [확정·출처: AX 추진방법론 v1.1 강의자료].
- **기존 시스템 맥락:** 신규 프로젝트. 기존 코드 없음. 진단 모델은 장동인 교수의 AX 프레임워크(두 개의 축, AX 가치 4단계, AI Native 4대 이정표, 전사적 AI 플랫폼, 메가 프로세스)를 기준으로 하고 외부 모델로 보완한다 [확정·출처: 2026-10-01 사용자 결정].

## 3. 목표 (Goals)

- 컨설턴트가 기업 1곳의 진단을 기업 등록부터 승인 보고서까지 이 앱 하나로 끝낸다
- 응답자는 로그인 없이 15분 안팎에 설문을 마친다 [가설]
- 결과 화면에서 12개 영역 점수·종합 단계·두 축 위치·카테고리 간 격차·경고·우선순위를 한 번에 본다
- 모든 점수 계산 규칙이 문서(6.1)로 공개되어 컨설턴트가 고객에게 설명할 수 있다

### 비목표 (Non-goals)

- 기업의 셀프 가입·결제
- 개인별 역량 점수·순위(인사 평가 오용 방지)
- 인사 시스템·그룹웨어 연동
- 컨설턴트 검토 없이 AI 보고서를 고객에게 자동 발송
- 업종 벤치마크 비교(데이터가 쌓인 뒤 이후 범위)

## 4. User Scenarios

### Scenario S1 — 직원이 설문을 끝낸다

- **사용자:** 비로그인 응답자(고객사 직원), 스마트폰
- **상황:** 회사 공지로 받은 설문 주소와 참여 코드를 들고 접속한다
- **목표:** 자기 회사를 찾아 직원 카테고리 설문을 끝낸다
- **흐름:** SCR-001 기업 검색·선택 → SCR-002 참여 코드 입력·카테고리 "직원" 선택·익명 안내 확인 → SCR-003 영역별 문항 응답 → 제출 확인 → SCR-004 완료
- **완료 조건:** Given 설문이 열린 테스트기업A When 직원 카테고리 문항에 모두 답하고 제출하면 Then 완료 화면이 보이고 응답 1건과 문항 수만큼의 답변이 저장된다

### Scenario S2 — 컨설턴트가 기업을 등록하고 설문을 연다

- **사용자:** 관리자(컨설턴트), 데스크톱
- **상황:** 새 고객사 진단을 시작한다
- **목표:** 기업을 등록하고 응답자에게 줄 주소와 참여 코드를 얻는다
- **흐름:** SCR-005 로그인 → SCR-006 기업 목록 → SCR-007 기업 등록 → SCR-008 기업 상세에서 "설문 열기" → 주소·코드 복사
- **완료 조건:** Given 로그인한 관리자 When 기업을 등록하고 설문을 열면 Then 응답자 검색(SCR-001)에 그 기업이 나타나고 6자리 참여 코드가 표시된다

### Scenario S3 — 컨설턴트가 결과를 계산하고 해석한다

- **사용자:** 관리자
- **상황:** 카테고리별 응답이 익명 기준 이상 모였다
- **목표:** 종합 단계, 두 축 위치, 인식 격차, 우선순위를 확인한다
- **흐름:** SCR-008 진행률 확인 → SCR-009 "결과 계산" → 사분면·영역 막대·격차 히트맵·경고·우선순위 확인
- **완료 조건:** Given 결과기업C(카테고리별 응답 기준 충족) When 결과 계산을 실행하면 Then 6.1 규칙으로 계산한 기대값과 같은 종합 단계·사분면·영역 점수가 표시된다

### Scenario S4 — 컨설턴트가 보고서를 확정한다

- **사용자:** 관리자
- **상황:** 결과 계산이 끝났다
- **목표:** AI 초안을 검토·수정해 승인하고 PDF로 저장한다
- **흐름:** SCR-010 "AI 초안 생성" → 섹션·로드맵 편집 → 저장 → 승인 → SCR-015 인쇄 화면에서 PDF 저장
- **완료 조건:** Given 결과가 있는 기업 When 초안을 생성·수정·승인하면 Then 보고서가 잠기고 인쇄 화면에 모든 섹션과 로드맵이 나온다

### Scenario S5 — 응답자가 틀린 코드나 닫힌 설문을 만난다 (실패)

- **사용자:** 비로그인 응답자
- **상황:** 참여 코드를 잘못 입력하거나 마감된 설문 주소로 들어온다
- **목표:** 무엇이 문제인지 알고 안전하게 멈춘다
- **흐름:** SCR-002 코드 오류 문구 → 5회 실패 시 10분 잠금 / 마감 설문은 닫힘 안내만 표시
- **완료 조건:** Given 틀린 코드 When 5회 연속 제출하면 Then 잠금 문구가 보이고 시작 버튼이 비활성화된다

### Scenario S6 — 익명 기준에 못 미친다 (실패)

- **사용자:** 관리자
- **상황:** 어떤 카테고리 응답 수가 익명 기준보다 적다
- **목표:** 응답자가 드러나지 않게 결과를 본다
- **흐름:** SCR-009 미달 카테고리 "표시 안 함" 안내 / 모든 카테고리 미달이면 계산 버튼 비활성
- **완료 조건:** Given 미달기업D When 결과 화면에 들어가면 Then 계산 버튼이 비활성이고 빈 상태 문구가 보인다

### Scenario S7 — AI 초안 생성이 실패한다 (실패)

- **사용자:** 관리자
- **상황:** AI 서비스 오류 또는 60초 초과
- **목표:** 보고서를 직접 써서 계속 진행한다
- **흐름:** SCR-010 오류 배너 → 섹션 직접 작성 → 저장
- **완료 조건:** Given AI 호출 실패 When 초안 생성을 누르면 Then 오류 문구가 보이고 섹션 입력은 계속 가능하다

### Scenario S8 — 고객사 담당자가 진행 현황을 본다

- **사용자:** 일반 사용자(고객사 담당자)
- **상황:** 사내 응답 독려 전에 현황을 확인한다
- **목표:** 카테고리별 응답 수와 기준 충족 여부를 본다
- **흐름:** SCR-005 로그인 → SCR-013 진행 현황 → 주소·코드 복사
- **완료 조건:** Given 테스트기업A 담당자 계정 When 로그인하면 Then 자기 회사의 카테고리별 응답 수만 보이고 결과·개별 응답은 보이지 않는다

### Scenario S9 — 권한 없는 접근과 세션 만료 (실패)

- **사용자:** 비로그인 사용자, 고객사 담당자, 관리자
- **상황:** 보호 화면 주소로 직접 들어오거나 세션이 끝났다
- **목표:** 로그인 후 원래 화면으로 돌아가거나 접근 거부를 안내받는다
- **흐름:** 보호 화면 → SCR-005(로그인 후 복귀) / 역할 불일치 → SCR-014
- **완료 조건:** Given 고객사 담당자 When /admin 주소로 들어가면 Then 접근 거부 화면이 보인다

### Scenario S10 — 컨설턴트가 문항과 평가 설정을 조정한다 (v1)

- **사용자:** 관리자
- **상황:** 파일럿 결과를 보고 문항 문구와 경계값을 바꾼다
- **목표:** 문항을 고치고 평가 기준을 바꿔 다음 계산에 반영한다
- **흐름:** SCR-011 문항 필터·편집 → SCR-012 평가 설정 저장 → SCR-009 다시 계산
- **완료 조건:** Given 큰 격차 기준을 1.2로 저장 When 다시 계산하면 Then 결과 스냅샷의 사용 설정에 1.2가 기록된다

## 5. 화면 정의 & 정보 구조 (Screen Contract)

| 로그인(SCR-005) | 허용 | 허용 | 허용 | 계정은 관리자가 만듦. 자가 가입 없음 |

| 자기 회사 진행 현황(SCR-013) | 불가 | 허용(자기 회사만) | 불가(관리자는  사용) | 카테고리별 제출 수만 표시. 결과·개별 응답 없음 |
| 문항 관리·평가 설정(, v1) | 불가 | 불가 | 허용 | 진행 중 설문이 있으면 문항 수정 경고 |

### 6.1 평가 규칙 (채점 계약)

계산 모듈(FR-021~FR-027)은 아래 규칙만 따른다. 기본값은 DATA-009에서 읽고, 계산할 때 쓴 값을 DATA-007.settings_used에 저장한다.

- **R1 문항 값:** 수준 문항(level)과 인식 문항(perception)은 0~4 정수다. 인식 보기 "전혀 아니다~매우 그렇다"는 0~4로 바꾼다. "모름"은 값 없이 is_unknown=true이며 평균에서 뺀다. 목표 문항(target)은 점수 계산에 쓰지 않고 R11에만 쓴다.
- **R2 영역 점수:** 카테고리 c, 영역 a에 대해 문항별 평균(모름 제외)을 내고, 그 문항 평균들을 다시 평균해 0~4 값을 얻은 뒤 25를 곱해 0~100 점수로 만든다(소수 첫째 자리 반올림). 전체 영역 점수는 익명 기준을 충족하고 그 영역 값이 있는 카테고리들의 영역 점수를 **같은 무게로** 평균한다(응답자 수로 가중하지 않음). 모든 문항이 모름이면 그 카테고리의 그 영역 값은 없음으로 둔다.
- **R3 단계:** 점수 0 이상 20 미만 L0 탐색, 20 이상 40 미만 L1 시도, 40 이상 60 미만 L2 정착, 60 이상 80 미만 L3 확산, 80 이상 L4 내재화. 단, A05(AX 가치 단계)는 rule_tags에 l4_gate가 붙은 문항(온톨로지·닫힌 고리)의 전체 평균이 3.0 이상일 때만 L4가 될 수 있고, 아니면 L3이 상한이다.
- **R4 축 점수:** 바탕 = A01·A02·A03, 가능성 = A04·A05·A06, 준비 = A07·A08·A09·A10·A11, 성과 = A12. 축 점수는 소속 영역 전체 점수의 가중 평균(DATA-009.area_weights, 기본 1.0)이다. 카테고리별 축 점수도 같은 방식으로 낸다(사분면 카테고리 점에 사용).
- **R5 사분면:** 가로 준비 축, 세로 가능성 축, 경계 50(DATA-009.quadrant_boundary). 준비 50 이상·가능성 50 이상 "AI Native 궤도", 준비 50 미만·가능성 50 이상 "혼돈의 확산", 준비 50 이상·가능성 50 미만 "통제만 있는 정체", 둘 다 50 미만 "탐색".
- **R6 종합 단계:** 12개 영역 전체 점수의 가중 평균을 R3 구간으로 바꾼 값에 병목 상한을 적용한다. ① A09(데이터·지식 자산) 단계가 L2 미만이면 종합은 최대 L2 ② A01(전략·리더십) 단계가 L1 미만이면 종합은 최대 L1. 상한이 적용되면 cap_reasons에 사유 문장을 넣는다. 두 상한이 모두 걸리면 낮은 쪽을 쓴다.
- **R7 인식 격차:** 공통 문항만 쓴다. 영역마다 기준 충족 카테고리 쌍(exec−staff, exec−axit, axit−staff)의 0~4 평균 차이(부호 포함, 소수 둘째 자리)를 낸다. 절댓값이 gap_major(기본 1.0) 이상이면 "큰 격차", gap_warn(기본 0.5) 이상 gap_major 미만이면 "주의". 기준 미달 카테고리가 낀 쌍은 계산하지 않는다.
- **R8 의견 분산:** 카테고리·문항별로 응답 수 3 이상일 때 rwg = 1 − (관측 분산 ÷ 2.0)을 계산한다(5점 척도 균등분포 분산 2.0, 결과는 0~1로 자름, 관측 분산은 표본 분산). 영역의 rwg는 문항 rwg 평균이다. rwg_threshold(기본 0.5) 미만이면 "의견 분산".
- **R9 인지 부족:** 카테고리·영역별 모름 비율 = 모름 답변 수 ÷ 그 영역 전체 답변 수. unknown_threshold(기본 30%) 이상이면 "인지 부족".
- **R10 경고:** ① 혼돈의 확산: 가능성 축 60 이상이고 A08 점수 40 미만 ② 위에서만 보이는 AX: 공통 문항 전체 평균에서 exec − staff가 1.0 이상(두 카테고리 모두 기준 충족) ③ 미관리 AI 사용 의심: staff의 rule_tags=ai_usage 문항 평균 3.0 이상이고 axit의 rule_tags=approved_tool_coverage 문항 평균 1.5 이하. 조건에 필요한 카테고리가 미달이면 그 경고는 판정하지 않는다.
- **R11 목표 단계:** 기본은 영역별 min(4, 현재 단계 + 1). (v1) 경영진 목표 문항 응답이 영역에 3개 이상 있으면 그 중앙값(정수 내림)을 쓰되 현재 단계보다 낮으면 현재 단계로 둔다.
- **R12 우선순위·시점:** 우선순위 점수 = (목표 단계 − 현재 단계) × 병목 가중(R6 상한을 만든 영역이면 2, 아니면 1) × 영역 가중치. 점수 내림차순, 같으면 현재 점수 낮은 순, 그래도 같으면 영역 코드 순. 시점: 30일 = 상한을 만든 영역과 "인지 부족" 플래그 영역(최대 3개, 우선순위 순) · 90일 = 30일에 없는 상위 2개 영역 · 365일 = 나머지 중 현재 점수가 다음 단계 경계보다 낮은 영역 상위 3개. 한 영역은 한 시점에만 들어간다.
