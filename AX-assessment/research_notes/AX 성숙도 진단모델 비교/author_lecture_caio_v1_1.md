# 저자 강의자료 요약 — 「기업의 AX 추진방법론(CAIO버전) v1.1」

> 출처: 장동인, KAIST 김재철AI대학원 CAIO 과정 강의자료(PDF, Google Drive, 2026-09-29 생성). 사용자 본인이 제공한 자료이며, 외부 사실이 아니라 **고객(저자)의 프레임워크**로 취급한다.
> 강의 안의 외부 인용(BCG 컨설턴트 실험, Anthropic Economic Research 2026-06-16 등)은 강의자료에 실린 내용 그대로이며 이 조사에서 원문을 검증하지 않았다.

## 1. 핵심 명제 (강의 "한줄 요약")
- 기업 AI 사용의 최대 문제는 환각(Hallucination)이며, AI가 고도화될수록 환각도 고도화되어 업무 전문가만 발견할 수 있다 → **환각을 발견·교정·책임지는 조직적 수단**이 필요하다.
- AX를 위해 기업이 할 일 4단계:
  1. 모든 비즈니스에 질문하고 그것을 **문제로 정의하는 능력**
  2. 현업이 일을 대하는 자세 변화 — **가짜 일을 찾아 없애고 진짜 일**을 한다
  3. **현업이 AI 기술을 배워** 자기 업무를 자동화한다
  4. 자동화 이후 **예측 → 시뮬레이션 → 최적화**로 올린다
- AX의 핵심에는 바이브 코딩이 있고, 현업 스스로 적용하는 것이 핵심이다. 전제조건은 **기업 데이터 통합**이다.
- "기업에서 AI 활용 수준은 CEO/임원의 수준이다." CEO/임원이 AI Technical Leader가 되어야 한다.

## 2. AI 프로젝트 실패 이유와 해결 방안
| 실패 이유 | 해결 방안 |
|---|---|
| 안 써도 당장 망하지 않는다 (사용 유인 부족) | 현업이 직접 구현, 모델 중립, 최고 모델 API 연결, 망분리는 하이브리드로 |
| **고립된 AI 조직** (외부 인력, 파일럿·보고만 많고 업무 적용 없음, 협업 부족) | **현업이 프로젝트 오너**, 현업·AI팀·IT팀 **공동 KPI**, 9단계 표준 업무 프로세스 정착 |
| **구성원들 간 AI에 대한 생각이 모두 다르다** (임원 기대치는 AGI 수준, 기술 이해는 부족) | CEO/임원이 직원보다 AI 공부를 더 많이 한다 |
| AI 전문가 부족이라는 오해 | 내부 인력 중심 + 외부 전문가 소수 채용 (도메인 지식 + AI 역량) |
| 외부 영입 vs 내부 역량 딜레마 | 의욕 있는 직원을 키우고 인센티브. 전 직원(CEO·임원 포함) AI 교육 |

- **AI 활성화 KPI 3종:** ① AI 적용 업무 제안 점수 ② 실제 구현 시 점수 ③ ROI 측정 후 긍정 효과 점수. 외부 전문가 별도 인센티브, 부서별 로드쇼·사례 발표.
- **AI 과제 추진 방안 비교표:** AI 전문가 영입 / 외주 / 내부 직원 교육을 비용·적용 시점·위험·지식 축적·회수 시점·기술 변화 대응·총비용으로 비교 → 내부 직원 교육이 총비용 최저.
- **추진 단계:** 사용자 위주 사내 **Vibe Coding TF** 결성 → 자기 업무 앱 직접 제작·공유 → 아이디어 수집 캠페인·워크숍 → 선정(좁고 깊은 분야, 구현 가능성, ROI, 구현 비용) 및 구현 → 임원 보고 → 전사 확대 계획(인력·예산·시간) → 임직원 교육·AI 붐 조성. AI팀은 전사 AI 표준(아키텍처·툴·KPI·방법론·마스터플랜) 설계.
- **사내 전문가 인정:** AI 도입 1차 목표 = 직원 생산성 향상. 대체 불안 해소("일찍 끝내면 일찍 가라"), 포상. "2000년대 6시그마 운동 → 2025년 AI 운동".

## 3. AI의 9단계 업무 프로세스 (designed by 장동인)
(1) AI 적용분야 결정(문제정의) → (2) dataset 준비 → (3) 데이터 전처리 → (4) feature engineering → (5) AI 모델 설계 → (6) Training → (7) Test(정확도·과적합) → (8) 결과 모델 검증 → (9) 실제 데이터 적용·사용.
- 고립형: 1~2는 현업, 3~9는 AI팀/IT가 분리 수행 → 결과 없음.
- 협업형: 현업 적극 개입, IT 지원(DW·Big data·AI data mart·MLOps·AutoML), 모델 실사용·피드백, 공동 KPI.

## 4. 성공하는 AI 도입 프로세스와 확장
- **문제정의 → PoC 검증 → 점진적 확산:** "좁고 예리한 문제정의"(→ 데이터가 자동으로 정의됨), **PoC 1개월 이내**, 성공하면 옆으로 확장, 연관 업무 flow별 구현.
- 문제정의가 잘못되면 필요 데이터가 과다하거나 정의 불가 → 과제화하면 반드시 실패.
- **횡적 확장:** 검증된 방법을 다른 제품·세대로(쉬움).
- **종적 확장 3단계:** ① 현상파악(pattern analysis) ② 인과분석(diagnostic/causal) ③ 문제해결 및 제어(solution & control: APC, R2R, FDC). Human-in-the-Loop vs Autonomous.
- **제조업 종적 확장 7단계 (위임 사다리):** 1 실환경 설치·성능 검증 → 2 실환경 데이터 추가 학습·단기 운영 → 3 쉬운 작업 직접 적용 → 4 고난이도 포함 직접 운영, 문제 시 사람에게 보고 → 5 자체 해결 가능하나 틀리기도 함 → 6 인간 경력자 수준 문제 해결 → 7 인간 개입 없는 자동화.

## 5. 문제정의 사고 프레임워크 (7개)
디자인 싱킹(고객 관점), 5 Why(근본 원인), JTBD(고객의 진짜 일), 제1원리 사고(문제 해체), 시스템적 사고(업무 프로세스 재정의), 문제해결의 증명(KPI를 실제로 움직이는가), AI를 위한 프롬프트/PRD 생성.

## 6. 가치 4단계의 구현 요소 (돈 되는 AI)
- "AI의 본질은 자동화가 아니라 최적화. 자동화는 사무실에, 최적화는 현장에 있다."
- 1 업무자동화 → 2 예측 → 3 시뮬레이션 → 4 업무최적화 (구현 난이도·업무 정의 명확성 증가, 비즈니스 가치 증가). HR·GTM·R&D 사례.
- 예측: 통계/ML/DL/Time-series Transformer, 백테스트(MAPE·RMSE), MLOps.
- 시뮬레이션: **온톨로지(기업의 디지털 트윈: 객체·관계·속성·규칙)** + What-if/Monte Carlo/DES/Agent-based.
- 최적화: 온톨로지(의사결정 변수·제약·목적함수) + 최적화 엔진(LP/MIP, 메타휴리스틱, 베이지안, RL). **예측 → 시뮬레이션 → 최적화 → 실행 → 피드백의 닫힌 고리**.
- AX의 목표는 보고서 자동화가 아니라 매출 증가·이익 증가·비용 감소·고객만족. 판단과 실행에 AI가 참여하는 기업 = AI Native.

## 7. 바이브 코딩·플랫폼·거버넌스
- 바이브 코딩 = SW의 소비재화: BRD 신속 작성 → 신속 구현 → 활용 → 폐기, 계속 활용 시 IT 부서에 정식 앱 요청.
- PRD는 인간이 최종 검토해야 함(가짜 실현가능성, 상식적 비즈니스 규칙 누락, 오버엔지니어링 위험). 실습 흐름: PRD → bkit(plan·design·do·check·act·report) → GitHub → Supabase → Vercel.
- AI 통합 플랫폼/Agent/Ontology가 ERP·SCM·PLM·CRM·MES·KMS·EDW·Graph·Vector DB와 연결. Agent 오케스트레이션(MCP·API 커넥터)으로 현업 요청 → 앱 자동 생성(반나절~2일).
- **무절제한 전사 바이브 코딩 6대 문제:** ① 검증 없는 코드 품질 ② 보안·데이터 유출 ③ 데이터 불일치·거버넌스 통제 불능 ④ 중복 개발·Shadow IT ⑤ 책임 소재 불분명 ⑥ 기술부채·자산화 실패 → 전사 AI Native 아키텍처(거버넌스·표준 플랫폼) 필요.
- **IT 부서 vs 현업 역할 분담:** IT = DB 설계·데이터 보안·데이터 통합·UI/UX 표준·Regression Testing·중복 방지·Shadow IT 방지·자산 카탈로그·토큰 사용 관리 / 현업 = PRD 작성, 업무 재정의(Process Reengineering), 업무 경험의 Skills 자산화.

## 8. 인재·역량 관련 명제
- 성공을 가르는 건 코딩 실력이 아니라 **문제 이해도(도메인 전문성)**; 사람은 WHAT, AI는 HOW. 현업의 능력은 "생성"이 아니라 **"검증"** (강의가 인용한 Anthropic Economic Research 2026-06-16 — 미검증).
- AI 활용이 성과 격차를 좁히는가 넓히는가: 일반 업무는 상향평준화, 도메인 특화 업무는 격차 확대 가능 (강의가 인용한 BCG 컨설턴트 GPT-4 실험 — 미검증).
- 시스템 1·2 사고, **시스템 2 사고의 아웃소싱** 위험, 환각의 고도화(법조계 허위 판례 사례).
- AI 시대 도태 3유형: AI를 답 얻는 기계로만 보는 사람 / 질문이 없는 사람 / SOP만 따르는 인력.

## 9. 진단 모델 설계에 주는 시사점 (코디네이터 해석)
- 책 원고에서 약했던 **인재·문화·변화관리** 영역을 강의자료가 상당 부분 채운다: 전 직원 교육, CEO/임원 AI 리터러시, KPI 3종, 인센티브·포상, 내부 역량 vs 외부 영입, 대체 불안 해소, Vibe Coding TF.
- 강의의 실패 이유 "**구성원 간 AI 인식 차이**"는 앱의 핵심 차별점(경영진–현업 인식 격차 분석)을 저자 본인의 방법론으로 정당화한다.
- 새로 영역화할 후보: **문제정의 역량**, **AI 추진 조직·협업 구조(현업 오너·AI팀·IT 공동 KPI)**, **환각 검증 체계(발견·교정·책임)**.
- 9단계 업무 프로세스, 성공하는 도입 프로세스(문제정의→1개월 PoC→확산), 종적 확장 3단계/7단계는 "대표 과제 진단" 문항의 행동 기준(BARS)으로 쓰기 좋다.
- 온톨로지·닫힌 고리는 가치 4단계 중 시뮬레이션·최적화 단계의 판정 기준(온톨로지 존재 여부, 실적 피드백 루프 여부)이 된다.
