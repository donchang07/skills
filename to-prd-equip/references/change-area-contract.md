# 변경 영역 계약

`to-prd`의 화면 정의 계약을 장비 소프트웨어용으로 바꾼 것이다. 변경 영역을 먼저 확정하지 않은 상태에서 FR이나 시험 기준을 완성했다고 판정하지 않는다.

## 1. 작성 순서

1. 장비·고객·현장 기준 버전을 정한다(11.2 #1).
2. 동결 영역 `FRZ-*`를 확인한다. 제품 정본에 이미 있으면 참조만 한다.
3. 변경 영역 인벤토리를 만든다.
4. 영역 항목마다 현재 값·목표 값·근거·허용 경로를 쓴다.
5. 장비 상태 매트릭스와 권한을 쓴다.
6. 영역 항목에서 `FR-*`, `SC-*`를 도출한다.
7. 증분 계약(기준 버전·허용 경로·롤백)을 쓴다.
8. 생성한 ID를 영역 항목에 다시 연결한다.

## 2. 영역 코드

| 코드 | 영역 | 예 | 기본 시험 수단 |
|---|---|---|---|
| `RCP` | 레시피·검사 조건 파라미터 | 검사 영역, 조명 값, 노출, 패키지 치수, 검사 항목 on/off | `[골든]` |
| `INS` | 검사 판정 기준 | 허용 공차, 범프 높이·직경·동일평면도 기준, 판정 로직 조건 | `[골든]` |
| `DEF` | 불량 분류 | 불량 클래스 추가·병합, 코드 매핑, 리뷰 화면 분류, AI 분류 확정 | `[골든]` |
| `HOST` | 호스트 연동 | SECS-II 메시지(S/F), CEID·RPTID·SVID·DVID·ECID·ALID, 레시피 다운로드, 원격 명령 | `[가상호스트]` |
| `LOG` | 물류·캐리어 | E84 핸드오프, E87 캐리어·로드포트 상태, E40/E94 작업 흐름, 맵 데이터 | `[가상호스트]` |
| `UI` | 장비 HMI | 운영 화면 항목, 리뷰 화면, 알람 표시, 권한별 메뉴 | `[단위]`·`[수동]` |

제품마다 영역 코드를 늘릴 수 있다. 늘리면 제품 정본 5.2 머리말에 정의를 추가하고 개정 번호를 올린다.

## 3. 동결 영역 `FRZ-*`

동결 영역은 PRD로 바꾸지 않는 부분이다. AI 생성·수정 대상이 아니며 bkit의 허용 경로에도 넣지 않는다.

| 열 | 의미 |
|---|---|
| ID | `FRZ-001` |
| 영역 | 3D 측정 엔진, 광학 보정, 영상 취득·스티칭, 모션·안전 인터록, SECS/GEM 통신 엔진 등 |
| 모듈·경로 | 저장소 경로 또는 모듈 이름. glob 허용 |
| 동결 이유 | 물리·광학 지식, 안전, 인증, 고객 승인 등 |
| 변경 시 절차 | 담당자·별도 검증·고객 승인. PRD 밖에서 진행 |
| 경계 인터페이스 | 변경 영역이 이 모듈을 호출할 때 쓰는 API·파라미터. 경계 인터페이스의 **사용**은 허용, **변경**은 금지 |

- 동결 영역은 제품 정본에서 정의한다. 고객 정본은 고객 특이 동결 항목만 추가한다.
- 변경 영역 항목이 동결 영역의 경계 인터페이스를 바꿔야 하면 FR로 만들지 않고 13장 결정 요청으로 올린다.
- 동결 영역을 비워 두는 것은 허용하지 않는다. 정말 없으면 `해당 없음 — 이유`를 쓴다. 장비 소프트웨어에서 이 이유는 드물다.

## 4. 영역별 필수 계약

모든 영역 항목은 공통 열을 가진다.

| 공통 열 | 의미 |
|---|---|
| ID | `RCP-001` 등 영역 코드 + 번호 |
| 항목 | 사람이 읽는 이름 |
| 현재 값 | 기준 버전의 값. `code-prd-equip`에서 왔으면 그 라벨(`[역추출]`·`[역추출·확인: …]`)을 유지 |
| 목표 값 | 이번 변경 후의 값 |
| 근거 | 고객 요청서·사양서 경로와 버전, 또는 제품 결정 |
| 허용 경로 | 이 항목 때문에 바뀌어도 되는 소스 경로 |
| 관련 FR·SC | 역연결 |

### 4.1 RCP 레시피·검사 조건

추가 열: 파라미터 이름(코드상 키), 단위, 범위, 기본값, 레시피 버전 호환(이전 레시피를 열 수 있는가), 호스트 다운로드 대상 여부.

### 4.2 INS 검사 판정 기준

추가 열: 판정 대상(측정값·특징), 조건식, 경계값 처리(이상·초과), 판정 결과(Pass·Fail·Review), **골든셋 기대 영향**(어떤 샘플의 판정이 바뀌어야 하고 어떤 샘플은 바뀌면 안 되는가).

### 4.3 DEF 불량 분류

추가 열: 클래스 코드, 이름, 상위 클래스, 호스트 보고 코드, 리뷰 화면 표시, AI 분류 사용 여부. AI 분류가 있으면 11.4 AI 판정 계약을 채운다(AI 결과와 사람 확정값은 다른 필드).

### 4.4 HOST 호스트 연동

추가 열: 메시지(SxFy)·방향, 관련 변수(CEID·RPTID·SVID·DVID·ECID·ALID와 형식), 트리거 조건, 응답·타임아웃(T3 등), 실패 시 동작, 근거 사양서 절·버전.

변수 ID 값(예: CEID 번호)은 고객 사양서에서 온 값이면 `[확정·출처]`, 기존 소스에서 읽은 값이면 `[역추출]`이다.

### 4.5 LOG 물류·캐리어

추가 열: 표준(E84·E87·E40·E94), 상태 전이(이전 → 이후), 트리거, 타이밍·인터록, 오류 복구.

### 4.6 UI 장비 HMI

화면 변경이 있을 때만 쓴다. 화면 ID(`UI-001`), 화면·영역, 표시 항목, 권한 레벨별 차이, 입력 검증, 행동 결과. 웹 앱 수준의 디자인 시스템·반응형은 요구하지 않는다. 기존 HMI 스타일을 따른다고 쓰면 된다.

## 5. 장비 상태 매트릭스

`HOST`·`LOG`·`UI` 항목은 아래 상태에서의 동작을 정의한다. 적용되지 않으면 `해당 없음 — 이유`.

| 축 | 상태 |
|---|---|
| 제어 상태(E30) | Offline · Online-Local · Online-Remote |
| 처리 상태 | Idle · Setup · Executing · Pause (제품 정의에 맞춰 이름 조정) |
| 통신 상태 | 연결 · 끊김 · 재연결 |
| 알람 | 알람 없음 · 경고 · 중알람(정지) |
| 캐리어(LOG 항목만) | 도착 전 · 도착 · 맵 확인 · 처리 중 · 완료 · 반출 |

상태 조합을 모두 쓰지 않는다. 항목의 동작이 달라지는 상태만 쓰고 나머지는 "그 밖의 상태: 동작 없음" 한 줄로 둔다.

## 6. 권한

최소 행위자는 `운영자`·`엔지니어`·`유지보수`·`호스트`다. 이름은 장비의 실제 권한 레벨에 맞춘다. 항목마다 보기·변경·승인 가능 여부를 쓴다. 레시피·판정 기준 변경은 누가 승인하고 감사 기록이 어디에 남는지 포함한다.

## 7. FR 도출

- 영역 항목의 현재 값 → 목표 값 변화마다 FR을 만든다. 한 FR이 여러 영역에 걸치면 나눈다.
- FR 열: `ID / 판정 가능한 요구사항 / 우선순위 / 영역 항목 / 허용 경로 / 관련 SC / 검증 방법`.
- 영역 항목이나 허용 경로가 없는 P0 FR은 Blocker다.
- 허용 경로가 `FRZ-*` 경로와 겹치면 Blocker다.
- 화면·영역 없는 공통 동작(로그, 백업)은 영역 항목 칸에 `공통 — 이유`를 쓴다.

## 8. 시험 도출

PRD에는 무엇을 검증할지만 쓴다. 시험 코드·이미지 목록은 쓰지 않는다.

| 변경 | 도출하는 SC | 측정 |
|---|---|---|
| RCP·INS·DEF 변경 | 영역 항목마다 `[골든]` SC 1개 이상 | 골든셋 ID·버전, 판정이 바뀌어야 할 샘플군과 바뀌면 안 될 샘플군, 기대 일치율 |
| 판정 무관 변경 | 회귀 `[골든]` SC 1개 (공통) | 골든셋 전체 판정 변화 0건 |
| HOST 변경 | 메시지·이벤트마다 `[가상호스트]` SC | 시나리오 ID, 메시지 순서·내용·응답 시간 |
| LOG 변경 | 상태 전이마다 `[가상호스트]` SC | 전이 순서, 인터록, 오류 복구 |
| 장비 상태 매트릭스의 비정상 상태 | 통신 끊김·알람 중 동작 `[가상호스트]` SC | 재연결 후 보고 누락 0건 등 |
| 타이밍·모션 | `[HIL]` SC | HIL 환경 ID |
| UI | `[단위]` 또는 `[수동]` + 이유 | 권한별 표시 |
| 증분 범위 | 공통 SC 1개 | 기준 버전 대비 변경 파일 ⊆ 허용 경로, 동결 영역 변경 0건 |

`[현장]`은 고객 라인에서만 재현되는 항목에만 쓰고 이유를 함께 쓴다.

## 9. 증분 계약

| 항목 | 내용 |
|---|---|
| 기준 버전 | 현장 소프트웨어의 태그·커밋. 없으면 Blocker |
| 허용 경로 | FR별 허용 경로의 합집합 |
| 동결 경로 | `FRZ-*` 경로의 합집합 |
| 예상 규모 | 파일 수·변경 줄 수 범위 `[추정]` |
| 산출 형태 | 패치·빌드·설치 패키지 |
| 롤백 | 이전 버전 복귀 방법과 데이터(레시피·설정) 호환 |
| 설치 조건 | 설치 창, 사전 백업, 고객 승인 |

## 10. feature 파생본

feature 파생본에는 해당 feature의 영역 항목 전체, 관련 장비 상태 행, 동결 영역 표 전체, 비목표 표 전체, 11장, 증분 계약, 15장을 포함한다.
