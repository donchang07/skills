# Code PRD Equip — 기존 장비 소스에서 현재 상태 PRD 추출

> 상태: 초안 v0.1 · 짝 스킬: `to-prd-equip` (change-area-v1) · 산출물 스키마: as-is-v1

이 스킬은 PRD를 쓰지 않는다. **지금 현장 소스가 무엇을 하고 있는지**를 변경 영역 항목 단위로 꺼내 `to-prd-equip`이 쓸 현재 값으로 넘긴다. 목표 값, FR, 시험 기준은 만들지 않는다.

품질 기준은 하나다.

> 핵심 개발자가 이 문서의 항목을 하나씩 근거 위치에서 열어 보고 "맞다·틀리다·모르겠다"를 30초 안에 판정할 수 있다.

## 왜 분리하는가

| | code-prd-equip | to-prd-equip |
|---|---|---|
| 입력 | 소스 코드(기준 버전), 설정·레시피 파일, 현장 로그 | 고객 변경 요청서, 사양서, 이 스킬의 산출물 |
| 질문 | 지금 무엇을 하고 있는가 | 무엇으로 바꾸고 어떻게 검증하는가 |
| 산출 | `_as-is/{customer}.md` (현재 상태, `[역추출]`) | 제품·고객 정본 PRD, feature PRD, 게이트 |
| 정확도 | 부분적. 드러난 동작은 복원, 이유·타이밍은 약함 | 입력이 확정이면 계약으로 확정 |
| 실행 시점 | 고객 정본이 없을 때 한 번, 이후 기준 버전이 바뀔 때 | 변경 요청마다 |
| 보안 | 소스를 읽으므로 고객 보안 등급의 제약을 그대로 받는다 | 소스를 직접 읽지 않아도 된다 |

역생성은 틀릴 수 있는 일이고, PRD 작성은 틀리면 안 되는 일이다. 두 일을 한 스킬에 두면 추정이 계약으로 섞여 들어간다. 그래서 이 스킬의 결과는 확인 전까지 PRD의 사실이 될 수 없다(`to-prd-equip` HG-E09).

## 운영 불변식

1. **현재만 쓴다.** 목표 값·개선 제안·리팩터링 의견을 문서에 넣지 않는다. 보이면 13절 "발견 사항"에 한 줄로만 남긴다.
2. **근거 없는 값은 쓰지 않는다.** 모든 항목은 `파일:줄` 근거를 하나 이상 가진다. 근거를 찾지 못한 항목은 값 대신 `모름`과 찾아본 위치를 쓴다.
3. **모든 값은 `[역추출]`로 나간다.** 핵심 개발자가 확인하면 `[역추출·확인: 이름 YYYY-MM-DD]`로, 틀리면 `[역추출·정정: 이름 YYYY-MM-DD]`와 정정 값으로 바꾼다. 이 스킬이 스스로 확인 라벨을 붙이지 않는다.
4. **신뢰도를 숨기지 않는다.** 항목마다 `높음`·`중간`·`낮음`을 쓴다(extraction-rules 3절).
5. **변경 지도 범위만 읽는다.** 동결 영역(측정·광학·영상 취득·모션·통신 엔진)은 내용을 추출하지 않고 경로와 경계 인터페이스 후보만 표시한다.
6. **소스를 옮기지 않는다.** 문서에는 식별자·상수·짧은 조건식(한 줄)만 쓴다. 함수 본문이나 여러 줄 코드를 붙이지 않는다.
7. **고객 보안 등급을 따른다.** 등급 B·C 고객의 소스는 고객이 허용한 환경(사내 망분리 서버, 현장 반입 키트)의 모델로만 읽는다. 실행 환경을 산출물 메타에 쓴다.
8. **기준 버전을 고정한다.** 한 문서는 한 태그·커밋만 다룬다. 작업 트리에 커밋되지 않은 변경이 있으면 멈춘다.

## 단계별 리소스

- Step 2·3: `references/extraction-rules.md` — 영역별 찾는 곳, 근거 규칙, 신뢰도, 대조 방법
- Step 4: `assets/as-is-template.md` — 산출물 구조
- Step 5: `scripts/validate_asis.mjs` — 근거·라벨·신뢰도·코드 붙여넣기 검사
- 예시: `examples/sample-as-is.md` — `to-prd-equip/examples/sample-customer-prd.md`의 앞 단계(가상)

## 입력과 산출물

| 입력 | 필수 | 내용 |
|---|:---:|---|
| 저장소 경로와 기준 버전(태그·커밋) | 예 | 현장 소프트웨어와 같은 버전 |
| 고객 코드·장비 모델 | 예 | 메타 |
| 보안 등급과 실행 환경 | 예 | 운영 불변식 7 |
| 변경 지도 | 아니오 | 제품 정본 5.1·5.2 또는 워크숍 결과. 없으면 extraction-rules 1절의 기본 지도 |
| 고객 사양서(GEM 매뉴얼 등) | 아니오 | HOST 항목 대조 |
| 현장 통신 로그·골든셋 판정 기록 | 아니오 | 대조(Step 3) |

| 산출물 | 역할 |
|---|---|

| `docs/00-pm/_as-is/{customer}.metrics.md` | 추출 정확도 지표(확인 후 갱신) |

## Step 0 — 준비

1. 저장소가 기준 버전에 있는지 확인한다(`git describe --tags`, `git status`). 다르거나 변경이 남아 있으면 멈추고 묻는다.
2. 보안 등급과 실행 환경을 확인한다. 허용되지 않은 환경이면 멈춘다.
3. 변경 지도를 읽는다. 없으면 기본 지도를 쓰고 메타에 `[기본값] 기본 변경 지도`라고 쓴다.

## Step 1 — 코드 지도

저장소 전체를 훑어 모듈을 영역 코드(`RCP`·`INS`·`DEF`·`HOST`·`LOG`·`UI`)와 동결 후보(`FRZ`)로 분류한 표를 만든다. 분류 근거(경로 이름, 핵심 식별자, SECS 메시지 처리기 등)를 함께 쓴다. 어디에도 넣기 어려운 모듈은 `미분류`로 둔다. 이 표가 이후 단계의 읽기 범위다.

## Step 2 — 영역별 추출

`references/extraction-rules.md` 2절의 영역별 규칙대로 항목을 뽑는다. 항목 ID는 `AS-RCP-001`처럼 `AS-` 접두를 붙여 PRD ID와 섞이지 않게 한다. `to-prd-equip`이 PRD로 옮길 때 새 ID를 부여하고 대응을 남긴다.

항목마다: 항목 이름, 현재 값(또는 `모름`), 근거(`파일:줄`, 여러 개 가능), 신뢰도, 고객 특이 여부(공통 코어 값과 다른가), 비고.

## Step 3 — 대조

자료가 있는 만큼 대조한다. 대조는 신뢰도를 올리는 증거이지 확인을 대신하지 않는다.

- HOST: 고객 사양서의 CEID·SVID·ALID 표, 현장 통신 로그에 실제로 나온 메시지와 비교
- INS·DEF: 골든셋 판정 기록과, 추출한 조건으로 예상한 판정의 방향이 맞는지
- LOG: 로그의 상태 전이 순서

결과를 항목의 `대조` 열에 `일치`·`불일치`·`대조 자료 없음`으로 쓴다. 불일치는 신뢰도를 `낮음`으로 내린다.

## Step 4 — 문서 작성

`assets/as-is-template.md` 구조로 쓴다. 동결 영역 후보, 변경 영역 항목, 고객 특이 차이, 모름 목록, 발견 사항을 분리한다. 확인표(`review.md`)는 항목 ID·근거·현재 값과 빈 판정 칸만 가진다.

## Step 5 — 검사

`node scripts/validate_asis.mjs <문서>`를 실행한다. ERROR가 있으면 고친 뒤 저장한다. 저장 여부를 묻지 않는다.

## Step 6 — 확인 반영 (사람)

핵심 개발자가 `review.md`의 판정 칸을 채우면 이 스킬을 다시 실행해 문서의 라벨을 바꾸고 `metrics.md`를 갱신한다.

| 지표 | 정의 |
|---|---|
| 담긴 비율 | 확인 단계에서 "빠졌다"고 추가된 항목을 포함한 전체 대비 추출 항목 비율 |
| 틀린 비율 | 정정된 항목 / 판정된 항목 |
| 모름 비율 | `모름` 항목 / 전체 |
| 신뢰도 보정 | 신뢰도별 틀린 비율 (높음에서 틀리면 규칙을 고친다) |

이 지표가 제안서의 "실험 1 · 역생성 정확도" 측정값이다.

## Step 7 — 넘기기

확인이 끝난 문서를 `to-prd-equip`의 역생성 결합 모드 입력으로 넘긴다. 확인되지 않은 항목이 남아 있어도 넘길 수 있지만, 이번 변경이 건드리는 항목은 `to-prd-equip`에서 Blocker가 된다.

## 보고

1. 저장 경로 3개, 기준 버전, 실행 환경
2. 영역별 항목 수와 신뢰도 분포, `모름` 수
3. 동결 영역 후보 경로
4. 대조 결과(불일치 항목)
5. 핵심 개발자에게 먼저 확인받을 항목 10개(신뢰도 낮음·불일치·고객 특이 순)

## 원칙

- **현재만, 근거와 함께, 확인 전에는 추정으로.**
- **넓게 읽고 좁게 쓴다.** 변경 지도 밖은 지도만 그린다.
- **틀린 확신보다 정직한 모름이 낫다.**
- **소스는 문서로 옮기지 않는다.**
