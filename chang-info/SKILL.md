# 검증형 인포그래픽 (chang-info)

공개자료를 근거로 한 주제를 인포그래픽으로 만든다.
핵심 가치는 **사실과 해석을 구분해 과대해석을 막는 것**이다. 화려함보다 근거 수준이 먼저다.

## 0단계. 유형 선택

| 유형 | 형식 | 언제 | 명세 | 예시 |
|---|---|---|---|---|
| V3 검증 시리즈 | 세로 A4 × 3장 | 공개내용과 해석을 나눠 깊게 검증 (시험·논문·사업) | references/style-guide.md, references/modules.md | examples/have-dreidel.md |
| L1 프로세스 도식형 | 가로 16:9 × 1장 | 정책·지침·표준의 의사결정 구조와 실행 절차 | references/landscape-layouts.md | examples/process-dowi.jpg |
| L2 플랫폼 프로필형 | 가로 16:9 × 1장 | 무기체계·제품·기술 하나의 핵심 정리 | references/landscape-layouts.md | examples/profile-vectis.jpg |
| L3 데이터 브리핑형 | 가로 16:9 × 1장 | 기사·보고서 수치 요약 (손실·비용·집계) | references/landscape-layouts.md | examples/brief-air-losses.jpg |

사용자가 유형을 말하지 않으면 자료 성격으로 고르고, 고른 유형을 첫 줄에 밝힌다.
가로형 예시 문구 전체는 examples/landscape-examples.md에 있다.

## 산출물

`_workspace/chang-info/{YYYYMMDD}_{slug}/` 아래에 다음을 만든다.

1. `ledger.md` — 사실 검증 장부 (templates/claims-ledger.md)
2. `storyline.md` — V3는 3장 구성안, 가로형은 영역별 문구 배치안
3. `page-n.prompt.md` — 이미지 생성 프롬프트 (이미지 모델 사용 시)
4. `page-n.html` + `page-n.png` — HTML 렌더 결과 (권장 경로)

## 작업 순서

### 1단계. 사실 검증 장부 작성
- 1차 자료(공식 발표, 정부·군 공개자료, 원 논문, 공시)를 먼저 찾는다.
- 모든 주장을 한 줄씩 장부에 기록하고 등급을 붙인다: `[공식]` `[논문]` `[보도]` `[해석]` `[미확인]`.
- 서로 다른 자료가 같은 대상을 가리키는지 확인되지 않으면 **연결하지 않는다**. 연결 여부 자체를 `[미확인]`으로 기록한다.
- 수치마다 분모·조건·집계 기준을 함께 적는다. (예: 100% = 수행한 14개 시험점 기준, CBO 방식 기준)
- 장부에 없는 수치·명칭·인용은 인포그래픽에 넣지 않는다.

### 2단계. 구성
- **V3**: 기본 골격 (제목만 주제에 맞게 바꾼다)

| 장 | 질문 | 제목 패턴 |
|---|---|---|
| 1/3 | 무엇이 공개됐나 | 공식 공개내용과 관련 결과를 구분해 봐야 한다 |
| 2/3 | 어떻게 작동하나 | ○○는 어떻게 작동했나 |
| 3/3 | 무엇이 입증됐나 | 무엇이 입증됐고, 무엇은 아직 아니다 |

  각 장은 상단 핵심 결론 박스 1개 + 섹션 A~D(또는 E) 4~5개. 섹션은 references/modules.md에서 고르고 한 장에 같은 모듈을 반복하지 않는다.
- **L1·L2·L3**: references/landscape-layouts.md의 화면 분할 표를 그대로 따르고 영역마다 문구를 배정한다.

### 3단계. 레이아웃 명세
각 섹션·영역에 대해 다음을 확정한다.
- 모듈 또는 영역 이름, 제목
- 들어갈 문구 (카드 3줄 이내, 한 줄 18자 안팎 / 가로형 불릿은 30자 안팎)
- 아이콘·삽화 지시 (무엇을 그릴지 구체적으로)
- 경고(빨강) 요소가 필요한 곳

### 4단계. 제작 — 두 경로
- **HTML 렌더 (권장)**: assets/html-base의 style.css·icons.js를 복사해 page-n.html을 쓰고 `python3 render.py <폴더> page-1 …`로 PNG를 만든다. 차트·픽토그램·수식·작은 글씨가 있으면 이 경로를 쓴다. 가로형은 .page 너비를 1672px로 바꾼다.
- **이미지 모델**: V3는 templates/prompt-template.md, 가로형은 templates/prompt-template-landscape.md를 채운다. 화면 문구는 전부 따옴표로 고정하고, 스타일 블록은 세 장 모두 같은 내용을 붙인다. 3D 히어로 렌더가 핵심인 L2에 적합하다.

### 5단계. QA
결과를 장부와 대조한다.
- 수치·날짜·고유명사 오탈자 (한글 렌더링 깨짐 포함)
- 장부에 없는 문구가 생겼는지
- `[미확인]`·`[보도]` 항목이 단정형으로 바뀌지 않았는지
- 픽토그램·막대 개수와 길이가 수치와 맞는지
- 출처 줄 위치, 페이지 번호(1/3…)
- 글자가 겹치거나 잘린 곳 (렌더 PNG를 직접 열어 확인)

이미지 모델 결과에서 글자 오류가 2회 이상 반복되면 HTML 경로로 전환한다. 정확한 텍스트가 이미지 품질보다 우선이다.

## 문장 규칙
- 결론은 근거 수준에 맞춘다. "입증", "완료", "인증"은 장부에 근거가 있을 때만 쓴다.
- 경고 문구는 무엇을 의미하지 **않는지**를 명시한다.
- V3 마지막 장에는 "보고서에는 다음처럼 쓰는 것이 근거 수준에 맞다" 형식의 최종 정리 문단을 둔다. 가로형은 "핵심 한줄 평가" 또는 "핵심 메시지" 한 문장으로 대신한다.
- 출처 줄: `출처: 기관/자료명(연도), 저자 et al., 논문명, 식별자(연도).` 가로형 L3은 우하단 `자료: …`.
