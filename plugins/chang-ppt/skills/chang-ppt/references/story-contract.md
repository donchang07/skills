# 스토리와 편집 계약

내용을 설계하거나 기존 슬라이드의 설명·도식을 개선할 때 읽는다. 공통 서체·색·좌표는 SKILL.md와 color-system.md를 따른다.

## 슬라이드 설계 명세

제작 전 각 장에 아래 항목을 작성한다. 덱의 핵심 질문과 중심 주장 아래에서 장별 전개가 이어져야 한다.

| 항목 | 의미 |
|---|---|
| slide_id / slide_index | 기존 PPT의 안정적인 SlideID와 현재 순서. 삽입·삭제 후에도 ID로 대상을 식별한다. 신규 덱은 생성 후 ID를 기록한다. |
| role | cover, profile, toc, part, content, closing. 결론·실행 제안 장은 content이며 Thank You가 closing이다. 제목에 Part라는 글자가 있다고 본문 혼합 장을 구분 페이지로 판정하지 않는다. |
| question / message | 청중의 질문과 이 장이 답하는 핵심 주장 |
| relation / reading_order | 비교·인과·순서·포함·피드백 등 관계와 실제 읽는 순서 |
| visual | 도형·표·차트와 각 요소·연결의 의미 |
| headline / detail | 강조할 한 문장과 다음 줄의 해석·조건·한계 설명 |
| evidence | 주장별 출처·기준일·단위·조건·확인 상태 |
| transition | 다음 장이 필요한 이유. 설계 명세에 저장하고 노트 반영은 편집 범위에 따른다. |
| caption_action | 기존 캡션의 유지·통합·대체와 보존할 조건 |

headline/detail은 분리된 필드로 작성한다. 첫 마침표로 문장을 나누지 않는다. 소수점·영문 약어를 문장 경계로 오인할 수 있다. 페이지 제외는 번호 목록이 아니라 role로 판정한다.

## Narrative 작성과 배치

- content 장에는 기본 제공한다. headline은 핵심 흐름·관계를 한 줄 Bold로, detail은 그 의미·판단 조건·한계를 다음 줄 Regular로 쓴다. 두 텍스트박스 모두 Pretendard 14pt, 가로 가운데 정렬한다. 두 줄 전체 높이와 간격을 계산해 설명 영역의 세로 중앙에 둔다.
- 제목이나 노드 이름을 되풀이하지 않는다. 예를 들어 인과 도식이면 무엇을 바꾸면 무엇이 달라지는지와 그 판단에 필요한 가정을 설명한다. 비교표이면 비교 기준과 선택 조건을 설명한다.
- 목차, Part 독립 구분, 표지, 프로필, Thank You에는 생성하지 않는다. 설명과 결론이 실제로 있는 혼합 장은 content로 분류한다.
- 강조 문장의 한 줄 여부는 실제 글꼴 폭으로 확인한다. 넘치면 핵심 표현 단축 → 중복 설명 축약 → 가용 영역 재배치 순으로 해결한다. 중요한 조건을 지우거나 본문 글자를 작은 각주로 낮추지 않는다. 사용자 요청 없이 강조 한 줄·설명 다음 줄·가운데 정렬을 바꾸지 않는다.
- narrative가 기존 캡션의 의미를 충분히 전달하면 통합·대체할 수 있다. 가상 예시 표시, 단위, 범위, 한계, 출처 정보는 반드시 남긴다. 기존 caption_action을 명세에 기록하고 보존 대상 도형 변경도 편집 계약에 반영한다.
- 설명과 출처의 공간을 먼저 예약한 뒤 비주얼을 배치한다. 출처는 고정 좌표를 유지한다. narrative는 콘텐츠 묶음에 포함하되 본문 도형과 충돌하지 않는 별도 영역을 확보한다. 일반 설명은 무배경이 기본이다. 사용자가 채택한 기존 narrative 패널은 해당 덱의 예외로 유지할 수 있으며 모든 새 덱에 강제하지 않는다.

## 근거와 의미 검토

사실·해석·가설·제안·가상 예시를 구분한다. 주장마다 출처 식별자, 확인 범위와 시점, 단위·분모·표본·적용 조건을 기록한다. 최신 정보나 확인되지 않은 전문 주장은 원문으로 확인한다. 근거가 없으면 수치·확정적 결론을 만들지 않고 미확인으로 표시한다. 관측값과 추정값, 상관과 인과, 예측과 실행 승인 조건을 혼동하지 않는다.

도형 QA는 문장과 그림을 함께 대조한다. 화살표 방향이 주장과 일치하는지, 분기마다 조건이 있는지, 피드백이 올바른 단계로 돌아오는지, 비교축·범례와 사분면 라벨이 맞는지 확인한다. 실선·점선의 모든 끝점과 교차점을 확대 렌더링으로 확인한다.

## 부분 수정 계약

작업 명세에 target_mode(new_deck/edit_deck/skill_update), 원본·결과 경로, 기준 스킬 경로·지문, 대상 SlideID, 허용할 도형·서식·노트 변경, 보존할 항목을 적는다. 원본과 결과의 고정 페이지·마스터·레이아웃·기존 노트·비대상 도형을 비교한다. 정렬만 변경하는 작업에서 본문이나 노트를 다시 작성하지 않는다.

노트는 기본 보존한다. 화면 설명만 수정하는지, 노트까지 보완하는지 명세에 적는다. 상세 출처 URL이 새로 필요하면 기존 노트를 지우지 않고 허용된 출처 구역에 추가하며 그 변경을 계약에 기록한다. 기존 노트 변경이 허용되지 않은 경우 별도 근거 명세에 기록한다.
