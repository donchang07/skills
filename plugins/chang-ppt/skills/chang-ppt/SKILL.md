# Chang PPT 설계 및 브랜드 기준

## 통합 작업 모드와 정본

- 신규 제작, 기존 PPT 개선, 스킬 자체 개선을 이 스킬에서 처리한다. 요청에 맞는 모드를 선택하고 입력·산출물·수정 범위를 기록한다. PPT 편집 요청으로 스킬 파일까지 수정하지 않는다.
- 이 폴더의 SKILL.md·references·template.pptx를 한 묶음의 기준으로 읽는다. 스킬 개발 시 저장소 `chang-ppt/`가 정본이고 개인 설치본은 배포 사본이다. 개인 설치본으로 발표를 제작할 때도 해당 폴더의 참조를 함께 사용한다. 실행 기록에 실제 기준 경로와 버전 또는 지문을 남긴다.
- 기존 PPT 개선에서는 사용자 파일을 출발점으로 사용하고 고정 페이지·마스터를 보존한다. 신규 제작에서는 동봉 템플릿을 사용한다. 원본을 덮어쓰지 않고 구분되는 결과 파일을 만든다.
- 내용 설계와 narrative 작성에는 [스토리·편집 계약](references/story-contract.md)을 읽는다. 반복 편집·렌더링·검증에는 [도구와 QA 절차](references/tooling-qa.md)를 읽는다. 전체 개편·역할별 병렬 작업·부분 재실행에는 [협업 절차](references/orchestration.md)를 읽는다.

## 적용 순서와 기준의 소유권

1. 사용자의 명시적 요청을 우선 적용하라. 자료가 없으면 수치·출처를 만들지 말라.
2. 이 파일의 페이지·서체·배치 규격을 유일한 공통 기준으로 사용하라.
3. 내용 설계 전 [presentation-design.md](references/presentation-design.md)를 읽어라.
4. 화면 제작 전 [layout-patterns.md](references/layout-patterns.md)와 [color-system.md](references/color-system.md)를 읽어라. 색상 HEX와 역할은 color-system.md에서만 정의한다.
5. 표 처리 전 [table-contract.md](references/table-contract.md)를 읽어라. 표 코드와 옵션의 계약은 이 파일에서 정의한다.
6. 권장 비율보다 실제 자료의 의미와 가독성을 우선하라. 예외를 조용히 확대하지 말고 제작 명세에 기록하라.

## 작업 흐름

- 청중, 사전 지식, 목적, 기대 판단·행동, 시간·슬라이드 수, 자료, 템플릿 제약을 확인하라. 부족한 정보에는 합리적 가정을 표시하라. 핵심 근거가 없으면 자료 확인 필요로 표시하라.
- 전체 질문과 중심 주장, 하위 질문, 전개 순서, 슬라이드별 연결을 설계하라.
- 각 장의 질문·메시지·표현 유형·필요 근거를 정의하라. 정의·논증은 텍스트 중심도 허용한다. 장식용 비주얼을 강제하지 말라.
- 각 장의 실제 문구, 시각 자료 구조, 위치·읽는 순서, 발표자 설명, 연결 문장, 출처를 작성하라.
- 콘텐츠 슬라이드에는 핵심 주장 한 줄 Bold와 다음 줄 Regular 설명으로 narrative를 기본 제공하라. 두 문장을 각각 가운데 정렬하고 두 줄 묶음도 설명 영역의 가로·세로 중앙에 둔다. Pretendard 14pt를 사용하며 목차·Part 독립 구분·표지·프로필·Thank You는 제외한다. 사용자의 생략·변경 요청을 우선하며 상세 계약은 story-contract.md를 따른다.
- 설계만 요청받으면 논리 구조와 제작 명세까지 출력하라. 신규 PPT는 동봉 template.pptx를 복사하고 기존 PPT 개선은 사용자 원본의 사본을 편집하라.
- 생성 후 렌더링하여 텍스트 넘침·겹침·줄바꿈·주석 가독성·마스터 침범을 검사하라. 사용한 렌더러와 미검증 범위를 정확히 보고하라.

## 페이지별 규칙

| 유형 | 포함·편집 | 제목·서식 |
|---|---|---|
| 커버 | 항상 첫 장에 포함한다. 원본 1번 슬라이드의 발표 주제 글자만 교체한다. 발표자 소개·배경·배치·서식을 보존한다. | 원본 템플릿 서식을 따른다. |
| 프로필 | 항상 두 번째 장에 포함한다. 원본 2번 슬라이드를 그대로 사용한다. | 원본의 작은 글씨와 placeholder도 보존한다. |
| 목차 | 기본으로 포함한다. 짧은 발표에서는 본문에 개요를 통합할 수 있다. | 콘텐츠 제목 규격을 따른다. |
| 섹션 구분 | 발표 길이와 전개에 따라 사용한다. | 섹션 제목 30pt Bold, Part 표시는 브랜드색을 사용한다. |
| 콘텐츠 | 논리 설계에 따라 구성한다. 원본 3~6번은 내용 예시이며 서식의 최종 기준이 아니다. | 아래 공통 규격을 따른다. |
| 결론·요청 | 본문 근거에서 도출한 결론과 다음 행동을 Thank You 앞에 배치한다. | 콘텐츠 규격을 따른다. |
| Thank You | 항상 마지막에 원본 마지막 슬라이드를 그대로 포함한다. | 원본의 서식·연락처·placeholder를 보존한다. |

슬라이드 수가 지정되면 커버·프로필·Thank You를 포함한 총수로 계산하라. 이 세 장보다 작은 요청은 사용자에게 범위 결정을 요청하라. 본문의 논리 순서는 목적에 맞춰 선택하되 고정 페이지를 훼손하지 말라.

## 템플릿과 마스터

- template.pptx를 기반으로 사용하라. 크기는 16:9, 13⅓ × 7.5인치다. 실제 PPTX 크기를 읽어 계산하라.
- 마스터·레이아웃의 왼쪽 청색 바, 검은 수평·세로줄, 하단 그라데이션, 우측 상단 삼각형, 슬라이드 번호를 삭제·이동·재작성하거나 가리지 말라.
- 콘텐츠의 제목·본문·날짜·footer placeholder는 제거하고 일반 텍스트박스를 사용하라. SLIDE_NUMBER만 보존하라. 고정 페이지는 이 처리에서 제외하라.
- 슬라이드 번호의 위치·서식·구조를 보존하라. 삽입·삭제 후 실제 순서대로 표시되는지 확인하라. 번호 표시 갱신은 콘텐츠/장식 재설계와 구분하라.
- 반복 머리글·날짜는 추가하지 말라. 출처는 아래 고정 출처 영역에 표시하고, 기준일·단위는 해당 자료 가까이에 표시하라. 고정 출처는 장식용 바닥글과 구분하라.
- 전체 배경은 흰색으로 유지하라. 고정 페이지의 원본 배경과 색은 예외다. 콘텐츠 내부의 연한 색상 영역은 승인 팔레트만 사용하라.

## 서체와 크기: 요소 역할로 판정

| 요소 | 서체·크기·굵기 |
|---|---|
| 콘텐츠·목차 제목 | Pretendard 24pt Bold, 네이비, 가운데 정렬 |
| 부제목 | Pretendard 16pt Bold, 네이비, 가운데 정렬 |
| 중제목 | Pretendard 18pt Bold |
| 본문·표 헤더·표 본문·도식 라벨·캡션 | Pretendard 14pt, 본문 Regular, 표 헤더 Bold |
| 핵심 수치 | Pretendard 16·14·12pt 중 역할에 따라 선택한다. 주된 수치는 16pt, 비교 수치는 14pt, 보조 수치는 12pt를 우선한다. 강조는 Bold·의미색·여백으로 표현한다. |
| 보조 주석·각주·출처 | Pretendard 10~12pt Regular |
| PowerShell·명령어·코드·로그 | Consolas 고정폭, 기본 14pt, Regular 또는 Bold |
| 고정 페이지·페이지 번호 | 원본 템플릿 서식을 보존한다. |

- 굵기나 들여쓰기만으로 중제목을 추정하지 말라. 역할을 명시하라. 일반 본문의 부분 Bold와 표 강조 셀 Bold는 허용한다.
- 중요한 본문을 작은 주석이나 12pt 보조 수치로 재분류하여 밀어 넣지 말라. 넘치면 축약·분할하라.
- 새로 작성하는 자연어는 Pretendard로 통일하라. 코드 서체는 Consolas를 우선하고 없으면 D2Coding, Noto Sans Mono CJK KR 순으로 고정폭 대안을 확인하라. 한글 주석의 글리프 지원과 정렬을 렌더링으로 확인하라.
- 코드 외 제작용 대체 서체를 임의로 사용하지 말라. Pretendard가 없으면 설치하거나 미확보 사실을 보고하라. 발표 PC의 대체 표시에는 의존하지 말고 가능한 경우 글꼴 포함 또는 PDF를 제공하라.
- PPTX의 latin/ea/cs를 해당 역할의 서체로 설정하라. sym/buFont의 기호 글리프는 보존하라. SVG의 새 텍스트에도 해당 서체를 지정하라.
- 원본 사진·화면 캡처·논문 그림 안의 글씨는 서체 통일 대상에서 제외하라. 새로 추가하는 주석은 위 규격을 따른다.

## 제목 및 콘텐츠 영역

- 제목 박스: y=0.22인치, 높이 0.50인치, 슬라이드 가로 중앙에 배치하라. 마스터 삼각형·번호와 겹치지 않는 폭을 사용하라.
- 부제목이 있으면 y=0.92인치, 높이 0.40인치에 배치하라. 없으면 빈 박스를 만들지 말라.
- 콘텐츠 좌우 경계는 x=0.65~12.83인치로 잡아 왼쪽 장식과 여백을 확보하라.
- 콘텐츠 상단은 부제목이 있으면 y=1.48, 없으면 y=1.03인치다. 하단은 y=7.18인치로 잡아 하단 장식을 피하라.
- 출처는 슬라이드 최하단의 왼쪽 가용 경계에 고정하라: x=0.65, y=7.02, 높이 0.22인치, 왼쪽 정렬, Pretendard 10pt, 배경·테두리 없음. 본문과 최소 0.24인치 간격을 확보하라. 여러 출처의 전체 URL·서지정보는 노트에 보존하고 화면에는 짧은 출처명을 표시하라. 출처가 없는 장에는 임의의 출처나 빈 박스를 만들지 말라. 고정 페이지는 원본을 보존하라.
- 자료·설명·캡션·주석의 내부 배치를 먼저 확정하라. 출처가 있는 장은 본문 하단을 y=6.78인치로 제한하라. 표와 텍스트를 포함한 전체 콘텐츠 묶음의 bounding box를 이 가용 영역의 가로·세로 중앙으로 같은 dx/dy만큼 이동하라. 도형을 각각 중앙으로 이동하지 말라. 박스 위치의 중앙 배치와 박스 내부 글자의 정렬을 구분하라.
- 단독 표는 가용 영역 가로 중앙에 놓아라. 좌우·상하 복합 화면에서는 표를 지정 영역 안에 배치하고 전체 콘텐츠 묶음으로 정렬하라.
- 마스터 도형·고정 페이지·제목·부제목·슬라이드 번호·고정 출처는 콘텐츠 묶음에 포함하지 말라. 출처를 중앙 정렬 계산이나 묶음 이동에 참여시키지 말라.

## 텍스트 박스 배경

- 의미 있는 도식 노드·분기·독립된 요약 박스에는 color-system.md의 연한 배경색을 사용하라. 긴 글을 강조하기 위해 화면 폭 전체를 색으로 채우지 말라.
- 일반 설명문·정의·지원 언어 목록·설치 단계 설명·명령어·코드·캡션·하단 핵심 문장은 기본적으로 배경·테두리 없이 글자만 표시하라. 번호별 설명이나 명령어 행 뒤에 긴 배경 띠를 반복하지 말라. 필요한 구분은 여백·정렬·얇은 구분선으로 표현하라.
- 제목·부제목·출처에도 새 배경 띠를 추가하지 말라. 표 셀의 배경색은 table-contract.md를 따르고 고정 페이지는 보존하라. 텍스트 박스에 색을 넣으라는 일반 요청은 의미 있는 박스에 적용하고, 개별 설명문의 배경 제거 요청이 있으면 그 요청을 우선하라.

## 시각 자료와 캡션

- 의미 전달에 기여하는 주된 표현 하나를 선택하라. 같은 질문을 돕는 보조 표현을 결합하라. 서로 다른 주장은 장을 나누어라.
- 표·데이터 차트·수정할 도식은 편집 가능한 네이티브 객체를 우선하라. 벡터 도식·아이콘은 SVG를 사용할 수 있다. 사진·화면 캡처는 고해상도 PNG/JPG를 허용한다. 래스터를 SVG로 감싼다고 선명도가 높아지는 것은 아니다.
- 하나의 의미 있는 시각 자료 묶음 아래에 14pt 캡션을 붙여라. 도식의 모든 노드에 별도 캡션을 강제하지 말라. 옆의 해석문이나 이미지 주석이 같은 내용을 충분히 설명하면 중복 캡션을 생략하고 명세에 기록하라.
- 캡션은 해당 비주얼과 묶어서 배치하라. 사진·논문 그림·데이터의 출처와 생성 이미지 표시를 유지하라.
- 장식용 이미지, 불필요한 3D·그림자·과도한 애니메이션을 제외하라. 단계별 공개는 설명에 필요한 때만 사용하라.

## 발표자 표현

- 발표 내용에서 자신을 장동인교수가 추천하는 등의 3인칭으로 지칭하지 말라. 추천·제안 또는 자연스러운 문장을 사용하라.
- 커버·프로필·원본 Thank You의 발표자 소개는 보존하라.

## 최종 점검

- 프로필이 항상 두 번째이며 고정 페이지가 원본 그대로인지 확인하라.
- 각 장의 질문·표현·근거·해석이 연결되는지 확인하라. 반론·조건·한계를 누락하지 말라.
- 서체 예외는 코드·원본 그림·고정 페이지에만 적용했는지 확인하라.
- 의미색과 분야색을 혼용하지 않았는지 확인하라.
- 표 코드를 실행하면 위치·캡션·줄바꿈을 다시 확인하라. 자동 처리 통과가 시각 검증을 대신하지 않는다.
- 출처 좌표가 본문 장마다 동일하고 표·텍스트 묶음이 중앙에 있는지 확인하라. 일반 설명·명령어·하단 문장에 긴 배경 띠가 남지 않았는지 확인하라.
- 점선·실선의 모든 연결 끝점과 화살표 방향을 확대 렌더링으로 확인하라. 연결선의 검토 방법은 layout-patterns.md를 따르라.
- 실제 검증하지 않은 결과를 PowerPoint 검증 완료라고 표현하지 말라.
