# 업무 브리프 — 정상 (PRD템플릿 v1.5 텍스트판)

과제명: 회의실 예약 승인 / 작성자: 총무팀 김OO / 사용 환경: 웹

## 1 업무 문제와 목표
- 현재 불편한 점: 총무 담당자가 회의실 예약 요청을 메신저로 받아 엑셀에 옮기고, 겹치는 예약을 직접 확인한다. 하루 30건 중 3~4건이 중복 예약으로 다시 조정된다.
- 원하는 변화: (팀) 중복 예약 0건. (사용자) 직원이 빈 회의실을 바로 보고 신청한다.

## 2 사용자와 업무 흐름
| 사용자 역할 | 볼 수 있는 정보 | 할 수 있는 일 |
|---|---|---|
| 직원 | 회의실별 빈 시간, 본인 신청 내역(예약 현황 화면 안의 목록) | 예약 신청, 본인 신청 취소 |
| 총무 담당자 | 전체 예약 | 승인, 반려(사유 필수) |
- 현재 업무 순서: 메신저 요청 → 담당자 엑셀 확인 → 승인 회신
- 앱을 사용한 뒤의 순서: 직원 신청 → 담당자 승인 → 직원이 예약 현황 화면에서 승인 상태 확인(메일·메신저 알림 없음)

## 3 필요한 화면과 기능
| 화면 또는 기능 | 누가 사용 | 보고 입력하고 누를 것 |
|---|---|---|
| 예약 현황 | 직원 | 날짜 선택, 빈 시간 클릭, 신청, 내 신청 목록과 상태, 취소 |
| 승인함 | 총무 담당자 | 대기 목록, 승인·반려 |
- 이번에 꼭 필요한 것: 신청, 승인·반려, 중복 방지
- 이번에 제외할 것과 이유: 외부 손님 예약 — 보안 절차 별도 / 반복 예약 — 1차 범위 축소
- 나중에 추가할 것: 캘린더 연동

## 4 업무 규칙과 예외
- 반드시 지켜야 할 업무 규칙: 같은 회의실·시간에 승인된 예약은 하나뿐이다(총무팀 운영 규정 3조). 시작 1시간 전까지만 취소할 수 있다.
- 예외와 처리 방법: 반려(사유 표시), 이미 찬 시간 신청(신청 불가 안내), 통신 끊김(다시 시도)
- AI를 사용하는 경우: 사용하지 않음

## 5 데이터와 필수 조건
- 저장할 정보: 예약(회의실, 시작·종료, 신청자, 상태, 반려 사유), 이력 1년 보존(총무팀 규정)
- 반드시 지킬 조건: 사내 계정 로그인

## 6 완료 기준과 참고 자료
- 반드시 끝까지 되어야 할 업무: 신청 → 승인 → 직원이 승인 확인
- 성공을 확인할 기준: 중복 예약 주 15건 → 0건, 사용 4주 후 총무팀장 확인
- 목표 일정: 모름
