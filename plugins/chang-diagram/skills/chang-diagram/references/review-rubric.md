# 심사 루브릭

두 심사자는 같은 그림을 다른 관점에서 독립적으로 본다. story-judge는 "무엇을 말하는가", visual-judge는 "그것이 막힘없이 보이는가"를 판정한다. 둘 다 그림을 고치지 않는다. 고치기 시작하면 판정이 자기 작업 변호가 되기 때문이다.

## 공통 규칙

- **근거 없는 점수 금지**: 모든 점수에는 근거(요소 id, 발화 번호, 자동 검사 항목, PNG에서 본 위치)를 단다.
- **점수 척도**: 1 실패(메시지를 해친다) / 2 미흡(처음 보는 사람이 오해하거나 막힌다) / 3 수용(의도대로 읽히지만 거슬리는 점이 있다) / 4 좋음(지적은 사소하다) / 5 탁월(더 고칠 이유가 없다). 기본값은 3이다. 4·5는 이유를 적어야 준다.
- **지적 형식**: `심각도 | 항목 | 위치(id) | 현재 | 제안 | 수정 대상(distiller/builder)`. 심각도는 🔴 필수(항목 ≤2를 만든 원인) / 🟡 권장 / 🟢 참고.
- **not_run**: 원문이 없거나 렌더가 없어 볼 수 없는 항목은 not_run으로 두고 점수 평균에서 뺀다. 추정으로 채우지 않는다.
- 이전 버전 보고서가 있으면 지적별로 `해결/미해결/새 문제`를 표시한다. 고친 쪽을 다시 깎거나, 처음 본 척 새 기준을 들이밀지 않는다.

## story-judge

### 0단계 냉독 (다른 파일을 열기 전에)

`02_diagram_v{N}.png`만 열고 아래를 먼저 `03_story_review_v{N}.md` 맨 위에 쓴다. 이 단계에서는 `00_source.md`, `01_story.md`, `01_spec.json`을 읽지 않는다. 의도를 알고 보면 그림이 실제보다 잘 읽힌다고 착각하기 때문이다.

1. 5초 인상: 이 그림이 말하는 한 문장
2. 시선 경로: 처음 본 요소 → 이어서 본 순서
3. 30초 요약: 흐름을 3문장 이내로
4. 막힌 곳: 뜻을 모르겠거나 순서가 헷갈린 지점

### 1단계 대조와 채점

냉독을 적은 뒤에 원문과 명세를 읽고 채점한다.

| 항목 | 질문 | 대조 방법 |
| --- | --- | --- |
| S1 메시지 | 냉독 5초 인상이 `01_story.md`의 5초 테스트 문장과 같은 주장인가 | 두 문장을 나란히 적고 같은 점·다른 점 |
| S2 원문 충실 | 결론·결정·분기·주체가 빠지거나 바뀌지 않았나, 원문에 없는 사실이 들어가지 않았나 | 원문 추출 표의 항목마다 그림 요소 id를 찾는다. 그림 요소마다 발화 번호를 역추적한다 |
| S3 구조 적합 | 고른 유형이 결론의 관계 형태(흐름·책임·시간·변화·구조·선택)와 맞나 | story-distill.md 2절 표와 대조, 더 나은 유형이 있으면 이름과 이유 |
| S4 서사 흐름 | 시작·전환점·결론이 시선 경로 위에 놓였나, focal이 전환점인가 | 냉독 시선 경로 vs 명세 reading_path |
| S5 라벨 | 라벨이 원문의 구체어인가, 같은 층위 라벨의 문법이 나란한가, "단계 1", "처리" 같은 빈 말이 없나 | 요소별 라벨 목록 검토 |
| S6 선택과 밀도 | 결론에 필요 없는 요소가 있나, 주 단위가 9개를 넘나, 제외 목록의 판단이 맞나 | 포함·제외 목록 검토 |

S2에서 사용자가 결정한 내용이 빠지거나 뒤바뀐 것, 원문에 없는 수치·주체를 넣은 것은 다른 점수와 무관하게 🔴이다.

S2에서 원문이 다른 언어이면 수치마다 다음을 대조한다: 주체(미국·민간·중앙값 등)와 기준 시점이 붙어 있나, 한정어(several, nearly, as little as, more than)가 같은 방향으로 옮겨졌나, 위·아래 연결이 원문에 없는 인과로 읽히지 않나. 주체 누락으로 전체 수치처럼 읽히거나 한정어가 반대로 옮겨진 것은 🔴이다.

제안 문구를 쓸 때도 같은 기준을 지킨다. 심사자의 제안이 원문과 어긋나면 그대로 반영된 오류가 다음 회차에 남는다.

## visual-judge

먼저 `02_check_v{N}.json`을 읽고 오류를 옮겨 적은 뒤, PNG를 전체 한 번·확대(문제 위치별) 한 번씩 본다. 자동 검사가 통과해도 눈으로 본 결과가 우선이다.

| 항목 | 질문 | 대조 방법 |
| --- | --- | --- |
| V1 자동 검사 | errors 0건인가, warnings는 정당한가 | `02_check_v{N}.json` |
| V2 연결 | 화살표 방향이 명세의 from→to와 같나, `undirected` 연결은 화살촉 없이 그려졌나, 끝점이 테두리에 닿나, 선이 글자·노드를 지나가지 않나, 교차가 1회 이하인가, 분기 라벨이 다 있나 | 명세 edges 목록과 PNG 한 개씩 대조. 명세에 edges가 없으면 not_run |
| V3 정렬·간격 | 같은 층위 노드의 크기·간격·기준선이 같나, 여백이 균형인가 | PNG + SVG 좌표 |
| V4 위계 | headline > 머리글 > 노드 > 주석 순으로 크기·굵기가 보이나, focal이 가장 먼저 눈에 들어오나 | 흐리게 본(축소) PNG에서 처음 보이는 요소 |
| V5 색 의미 | 승인 팔레트인가, 강조색 1~2개인가, 같은 색이 같은 의미인가, 색만으로 의미를 전달하지 않나 | 명세 role·style과 실제 색 |
| V6 가독성 | 최소 글자 크기, 대비 4.5:1, 노드 줄 수가 `00_packet.md`의 density 상한 이하, 수치·단위가 줄 사이에서 끊기지 않나, 슬라이드 축소(50%)에서도 읽히나 | 줄 수는 PNG에서 눈으로 센다(자동 검사의 `too_many_lines`·`number_break`와 대조). 50% 축소 이미지를 만들어 본다 |

자동 검사 error가 남아 있거나 화살표 방향이 명세와 반대면 🔴이다.

## 통합 판정 (메인)

```
통과 = 🔴 0건
     AND 실행된 모든 항목 ≥ 3
     AND story 평균 ≥ 4.0 AND visual 평균 ≥ 3.5
```

- 통과하지 못하면 🔴와 2점 항목부터 수정 대상별로 묶어 보낸다. 🟡는 수정 회차에 여유가 있을 때 반영한다.
- 최대 2회 수정. 2회 뒤에도 남은 🔴는 사용자 보고에 그대로 적고, 원인이 밀도라면 분할안을 함께 제안한다.
- 점수와 판정은 `05_manifest.json`에 버전별로 남겨 이후 스킬 개선의 근거로 쓴다.

## 경량 재심사 (통과 뒤 small_fix)

두 심사를 통과한 그림에 남은 🟡·🟢를 메인이 문구 몇 개만 고쳐 반영했을 때 쓴다. 구조·배치·유형이 바뀌면 경량 재심사가 아니라 정식 재심사다.

| 바꾼 것 | 재심사 |
| --- | --- |
| 수치·주체·한정어·라벨의 의미(S2·S5 관련) | story-judge가 바뀐 요소 id만 원문과 대조해 `03_story_recheck_v{N}.md`에 해결/미해결/새 문제를 적는다. 냉독·전체 채점은 생략하고 이전 점수를 유지한다 |
| 줄바꿈·간격·색처럼 형식만 | `render_check.py` errors 0 확인으로 끝내고 manifest에 "형식 small_fix, 재심사 생략"을 적는다 |

경량 재심사에서 새 🔴가 나오면 정식 재심사로 전환한다. 재심사를 생략한 사실을 숨기지 않는다.

## 보고서 형식

`03_story_review_v{N}.md`, `03_visual_review_v{N}.md`:

1. (story만) 냉독 4줄
2. 항목별 점수 표: 항목 | 점수 | 근거
3. 지적 표: 심각도 | 항목 | 위치 | 현재 | 제안 | 수정 대상
4. 이전 지적 추적(v2부터)
5. 심사자 판정: 통과 / 수정 필요, 평균 점수, not_run 항목
