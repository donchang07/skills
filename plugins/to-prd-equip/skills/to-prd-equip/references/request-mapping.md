## 1. 읽기

요청서는 Markdown이다. Word로 받은 경우 `pandoc -t markdown`으로 읽는다. 요청서 버전이 이 문서와 다르면 PRD 메타 `입력`에 차이를 기록한다.

## 3. 모름 처리

| 요청서 값 | 필수 항목 | 그 밖의 항목 |
|---|---|---|
| 내용 있음 | `[확정·출처: 고객 변경 요청서 날짜]` | 같음 |
| 모름·빈칸 | 객관식 질문(4절) | `[기본값]`, 범위·시험이 달라지면 13장 |

필수 항목: **고객·장비·현재 버전, 변경 내용, 변경 영역, 완료 확인 방법, 시험 데이터 확보 여부**.

## 4. 필수 항목 질문

한 번에 최대 4문항, 전체 2회 이내. 첫 선택지를 `(추천)`으로 둔다. 질문에는 FR·SC·FRZ 같은 ID를 쓰지 않는다.

| 필수 항목 | 질문 | 무응답 시 |
|---|---|---|
| 현재 버전 | 현장 장비의 소프트웨어가 저장소의 어느 버전인가요? ① 출하 태그 그대로 (추천) ② 현장 수정본 있음 ③ 모름 | 중단 — 기준 버전 없이는 증분을 만들지 않음 |
| 변경 영역 | 이번 요청이 바꾸는 곳은? ① 검사 판정·불량 분류 ② 호스트 보고 ③ 물류 ④ 화면만 (복수 선택) | 소스 진단 결과로 `[기본값]` + 13장 |
| 완료 확인 | 고객은 무엇으로 완료를 확인하나요? ① 지정 시료 판정 결과 (추천) ② 호스트 시나리오 통과 ③ 둘 다 ④ 현장 생산 투입 후 | ③ `[기본값]` + 13장 |
| 시험 데이터 | 판정 확인용 이미지를 사무실에서 쓸 수 있나요? ① 있음 (추천) ② 고객 현장에서만 ③ 없음 | ② `[기본값]`, `[골든]` SC를 현장 반입 키트로 실행 + 13장 |

답은 `docs/00-pm/_interview.md`에 `날짜 / 문항 / 선택 / 반영 위치 / 상태`로 기록한다.

## 5. 비목표와 동결 영역

- 요청서 7장 항목은 `NG-*`가 된다. 다시 검토할 시점이 없으면 `[기본값] 다음 업그레이드 요청 시`.
- 요청이 동결 영역(`FRZ-*`)을 건드리면 FR로 만들지 않는다. 13장에 "동결 영역 변경 필요"로 올리고 담당자·절차를 적는다.

## 6. AI 판정 계약

불량 분류 등에 AI를 쓰면 to-prd와 같은 규칙으로 11.4를 채운다. AI 결과와 사람 확정값은 다른 필드이며, 확정·되돌리기는 FR과 `[골든]` 또는 `[단위]` SC로 검증한다.
