# 착수 게이트 (장비용)

목적은 "이 PRD만 받은 bkit이 기준 버전·변경 영역·동결 영역·시험을 추측하지 않고 Plan과 Design을 시작할 수 있는가"를 판정하는 것이다. **Hard Gate가 점수보다 우선한다.** 채점·판정·다시 읽기 절차는 `to-prd/references/gate-checklist.md` 11~12절과 같다.

## 1. 기계 검사

`node scripts/validate_prd.mjs <PRD 파일>`을 정본과 모든 파생본에 실행한다. `ERROR`는 최소 Major이며 아래 Hard Gate와 겹치면 Blocker다.

## 2. Hard Gate

| ID | 조건 |
|---|---|
| HG-E01 | 활성 `RCP/INS/DEF/HOST/LOG/UI/FR/SC/NG/FRZ` ID가 유일하고 상호 참조와 feature 분해표에 빠짐없이 연결된다. |
| HG-E02 | 동결 영역 표(5.1)가 있고 각 `FRZ-*`에 모듈·경로, 이유, 변경 시 절차, 경계 인터페이스가 있다. |
| HG-E03 | 변경 영역 인벤토리(5.2)의 모든 항목에 상세 행이 있고 현재 값·목표 값·근거·허용 경로가 있다. |
| HG-E04 | 어떤 FR의 허용 경로도 `FRZ-*` 경로와 겹치지 않는다. |
| HG-E05 | 고객 정본이면 현장 기준 버전(태그·커밋)이 `[확정]`이다. 제품 정본이면 공통 코어 기준 버전이 있다. |
| HG-E06 | 모든 P0 FR에 영역 항목 ID·허용 경로·SC·검증 방법이 연결된다. |
| HG-E07 | 판정을 바꿀 수 있는 RCP·INS·DEF 항목마다 `[골든]` SC가 있고 골든셋 ID·버전과 기대 영향(바뀔 샘플군·바뀌면 안 될 샘플군)이 있다. |
| HG-E08 | HOST·LOG 항목마다 `[가상호스트]` SC가 있고 시나리오 ID가 있다. |
| HG-E09 | 이번 FR이 바꾸는 항목의 현재 값에 확인되지 않은 `[역추출]`이 남아 있지 않다. |
| HG-E10 | P0 SC가 모두 `[현장]`이 아니다. `[현장]` SC는 사무실 재현 불가 이유가 있다. |
| HG-E11 | 11.1에 `[단위]`·`[골든]`·`[가상호스트]` 실행 명령(또는 결정 요청과 fallback)이 있고, 11.2 10칸이 모두 있다. |
| HG-E12 | 15장 완료 조건이 세 관문(match rate, 11.1 시험 통과, 범위 감시)을 모두 포함한다. |
| HG-E13 | 5.10 증분 계약에 기준 버전·허용 경로·동결 경로·롤백이 있다. |
| HG-E14 | FR이 NG-*를 구현하지 않는다. AI 기능이 있으면 11.4가 있고 AI 결과와 사람 확정값이 다른 필드다. |

## 3. 추적 연결표

| FR | 영역 항목 | 허용 경로 | SC | 시험 수단 | feature | 끊긴 칸 |
|---|---|---|---|---|---|---|

다음을 찾는다: 영역 항목 없는 FR, FR 없는 변경 항목(현재 값 ≠ 목표 값인데 FR 없음), SC 없는 FR, 시험 수단 규칙 위반(RCP·INS·DEF인데 `[골든]` 없음 등), 어느 feature에도 속하지 않는 FR, 정본과 파생본 불일치.

## 4. 보안·데이터 검사

- PRD 본문에 고객 이미지·로그·사양서 원문이 붙어 있으면 Blocker다. 경로·버전·해시만 허용한다.
- 보안 등급 C인데 11.1 시험 명령이 외부망을 전제하면 Major다.

## 5. gate 파일 구성

to-prd와 같고, "화면 계약 완결성 표" 대신 "변경 영역·동결 영역 완결성 표"를 쓴다.
