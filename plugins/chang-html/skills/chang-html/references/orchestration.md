# 협업 절차 (메인 · 제작 · 검수)

새 교안, 장 추가, 디자인 개편, 강사용, 검수 재실행 때 읽는다. Claude Code에서는 `/chang-html`로 호출한다. 현재 환경에 있는 위임 도구만 쓰고, 없으면 순차로 실행하되 병렬로 했다고 보고하지 않는다.

**실행 모드:** 생성·검증. 만든 사람은 자기 결과를 채점하지 않는다. 같은 맥락을 공유하면 검수가 독립성을 잃기 때문이다.

## 역할

| 역할 | 맡는 일 | 쓰기 범위 |
|---|---|---|
| 메인 | 요청 해석, 사실 조사, 디자인 브리프, 내용 원고(프롬프트 전문), 강사 노트 JSON, 최종 확인, 배포, 사용자 보고 | `_workspace/00_packet.md`, `02_design_brief.md`, `05_content_*.md`, `{RUN}/03_instructor_notes_v{N}.json` |
| `chang-html-builder` (opus) | 원고를 원본 HTML로 옮기고 빌드, 검수 지적 반영 | `src_v{N}.html`, 결과 HTML 2개, `_workspace/03_builder_log.md`, `_workspace/build_check_v{N}/` |
| `chang-html-reviewer` (opus) | 점검표 실행, 캡처를 직접 열어 판정. 읽기 전용(Edit·Write 없음) | `_workspace/review_r{k}/`(Bash로만), 보고서는 반환값 |

플러그인으로 설치하면 이름 앞에 `chang-html:`이 붙는다. 사용자 정의 에이전트가 세션에 없으면 같은 정의 파일 내용을 기본 서브에이전트에 넘기고 그 사실을 로그에 적는다. 같은 HTML을 두 에이전트가 동시에 쓰지 않는다.

## 작업 폴더

- `{RUN}` = 대상 프로젝트의 `_workspace/chang-html/{YYYYMMDD}_{주제}/`. 원본(`src_v{N}.html`), 결과 HTML, 노트 JSON은 `{RUN}`에, 패킷·브리프·원고·로그·검수 보고서·캡처는 `{RUN}/_workspace/`에 둔다. 스킬 설치 폴더를 작업 폴더로 쓰지 않는다.
- `00_packet.md`: 모드, 사용자 요청 원문, 해석, 청중·과제 이름·실습 환경, 원본과 기준 버전, 결과 파일 이름, 새 프롬프트 id 목록, 장 번호 변화, 배포 위치, 완료 기준. 후속 요청은 아래에 「v{N} 추가」 절로 덧붙인다.
- 기록 파일: `03_builder_log.md`(제작 담당이 버전별 절 추가), `04_reviewer_report_r{k}.md`(메인이 반환값을 저장).

## 흐름

1. **준비(메인):** 패킷 작성. 새 사실(제품 기능·필요한 키·모델 이름)은 웹으로 확인하고 출처와 날짜를 원고에 적는다. 디자인 브리프는 [design-system.md](design-system.md) 기본값에서 시작한다.
2. **원고(메인):** `05_content_*.md`에 배치, 장 제목과 리드, 표 값, 프롬프트 전문(코드 블록 바로 앞 줄에 `(id: …)`), 강사 노트 추가분을 쓴다. 제작 담당은 이 글자를 바꾸지 않는다.
3. **제작(builder):** 기준 버전을 복사해 `src_v{N}.html`을 만들고 원고를 넣은 뒤 `build.py`로 두 파일을 만든다. 자체 확인(검사기·캡처)은 하되 통과 판정은 하지 않는다. 원고에 없는 문장을 쓰면 로그에 「제작 담당 작성」으로 표시한다.
4. **검수(reviewer, 새 에이전트):** [tooling-qa.md](tooling-qa.md) 점검표. 반환 보고서를 메인이 `04_reviewer_report_r{k}.md`로 저장한다.
5. **반복:** FAIL이면 보고서 경로를 제작 담당에 넘겨 해당 항목만 고친다. 원고 자체의 문제(🟡 중 「정본 문제」)는 메인이 원고를 고친다. 최대 2회. 남은 🔴는 통과로 바꾸지 않고 사용자에게 보고한다.
6. **완료(메인):** PASS 보고서를 직접 읽고 캡처 몇 장을 연다. 사소한 🟡을 메인이 고치면 `validate.py`·`render.mjs`를 다시 돌리고 로그에 「메인 보정」을 남긴다. 내용이 바뀌는 수정은 다시 검수에 넘긴다.
7. **배포·보고:** [deploy.md](deploy.md). 사용자에게는 결과, 남은 🟡, 강의 전 확인할 것만 짧게 보고한다.

## 부분 재실행

- 같은 교안의 `{RUN}`이 있으면 후속 요청으로 본다. 바뀐 부분만 원고로 쓰고 제작·검수를 다시 돌린다. 검수는 이전 버전 대비 바뀐 곳과 프롬프트 전체 대조를 반드시 한다.
- 장 추가·이동 뒤에는 `renumber.py`로 장 id·레일·노트 표식을 다시 매기고, 노트 JSON 키와 본문 상호 참조(「09장」「10-4」)를 맞춘다. 카드 번호가 순서대로 읽히는지도 본다.
- 디자인만 바꾸는 요청(글꼴 등)은 「내용 불변」을 패킷에 적고, 검수는 본문 텍스트 동일성을 대조한다.

## 오류 처리

- 일시적 도구 오류는 원인을 확인하고 1회 재시도한다. 사용량 한도·권한 거부는 재시도하지 않고 남은 산출물을 보고한다.
- 렌더링을 못 했으면 정적 검사만으로 통과 처리하지 않고 not_run으로 보고한다.
- 에이전트가 남긴 빈 곳을 메인이 추측으로 채우지 않는다.

## skill_update 모드

이 스킬 자체를 고칠 때는 팀 없이 메인이 지침·참조·도구·플러그인 사본의 영향 범위를 대조해 고치고, 저장소 루트에서 `node scripts/build-chang-html-plugin.mjs` 후 `--check`를 돌린다.
