# 실습 프롬프트 작성 규칙

참가자가 Claude Code에 붙여 넣는 모든 지시를 복사 버튼 상자로 만든다. 원고에서 메인이 전문을 쓴다.

## 기본 형식

```
{작업 위치}에서 작업해 주세요.
1. …
2. …
3. 결과는 {결과 파일 경로}로 저장해 주세요.

[완료 조건]
- {파일·개수·형식처럼 눈으로 확인할 수 있는 조건}
```

- 한 프롬프트는 한 결과 파일을 만든다. 결과 파일 경로를 반드시 적는다.
- 완료 조건은 참가자가 결과를 보고 직접 대조할 수 있는 문장으로 쓴다(「8개 답과 근거 문장이 있다」).
- 원문에 없으면 「원문에 없음」, 검색에 없으면 「검색된 조각에 없음」처럼 없을 때의 답을 지정한다. 지어낸 답을 가려내는 문항(예: 원문에 없는 가격)을 연습문제에 하나 넣는다.

## 연습문제 설계와 시험 실행

- 교안을 배포하기 전에 메인이 모든 실습 프롬프트를 실제로 한 번 끝까지 실행한다(「시험 실행」). 예상 결과 표는 가설이므로, 시험 실행 결과와 다르면 **문항이 틀린 것**으로 보고 문항을 바꾼다. 표만 고쳐 맞추지 않는다.
- 문제 유형(예: RAG의 P1~P5)마다 그 유형에서 실제로 실패하는 대표 문항을 하나 이상 둔다. 후보 문항을 여러 개 만들고, 검색만 먼저 돌려 정답 조각이 상위 결과에 빠지는지 확인한 뒤 고른다(예: 흩어진 사실은 같은 이름이 원문 여러 곳에 나오는 문항, 문맥 잘림은 이름과 수치가 조각 경계에서 갈라지는 문항, 표현 불일치는 자막 오인식처럼 질문과 원문의 낱말이 다른 문항).
- 해결책 장의 방식들도 같은 문항으로 시험 실행해, 예상 결과 표의 각 칸(해결·부분)이 실제와 맞는지 확인한다. 다르면 표에 「(시험 실행에서는 해결)」처럼 실제 결과를 함께 적는다.
- 원문에 답이 없는 대조 문항을 하나 둔다. 모든 방식이 「없음」이라고 답해야 정답이다. 이 문항으로 어떤 방식도 실패하지 않으면 「대조 문항」이라고 밝히고 실패 유형의 대표 문항으로 쓰지 않는다.
- 「없음」 답에는 두 가지 실패가 있다. 없는 내용을 지어내는 것과, 원문에 있는데 「없다」고 단정하는 것이다. 검색 방식은 뒤쪽 실패가 더 흔하므로 판정 기준에 둘 다 넣는다.
- 판정은 원문 전체와 대조하고, 근거 문장은 원문과 글자 단위로 일치하는지 스크립트로 확인한다.
- 문항 수를 바꾸면 교안 전체의 표기를 함께 바꾼다: 문항 표, 문항 파일 프롬프트, 「Q1~Qn」, 「n문항」「n개 답」「n행」, 결과 파일 이름(`q1.txt ~ qn.txt`처럼 소문자 표기 포함), 완료 조건. 바꾼 뒤 이전 숫자가 남았는지 검색한다.
- 연습문제를 일부러 어렵게 만든 원문 특성(예: 자막 오인식 「Grock 3」)은 원문에서 고치지 않는다. 강사 노트에 그 이유를 적는다.

## 영상 자막으로 원문 만들기

- 자동 자막은 영상 없이 자막만 받는다(yt-dlp). 시간 표시, 태그, 되풀이 줄, 음악 표기를 지우고 문단으로 잇는다.
- 원문은 연설 첫마디로 시작해야 한다. 오프닝 영상 내레이션·사회자 소개와 끝부분 뮤직비디오 가사는 잘라 내고, 연사의 마지막 인사말은 남긴다.
- 도구가 처음 나오면 무엇인지, 왜 필요한지, 다른 쓰임을 짧은 설명 상자로 둔다(예: 「yt-dlp란?」). 형식 이름은 풀어 쓴다(예: SRT(자막파일)).

## 방식별 짝: 만드는 프롬프트 + 질문 스크립트

- 기술·방식을 소개하는 장에는 방식마다 「만드는 프롬프트」(준비·색인·데이터 만들기)와 「질문 스크립트」(같은 연습문제로 묻고 근거 남기기)를 짝으로 둔다. 소개만 하고 만드는 법이 없으면 결함이다.
- 질문 스크립트는 그 방식의 강약이 드러나는 문항을 고르고(예: 흩어진 사실, 근거 없음), 근거 표시 방법(원문 문장·조각 번호·페이지 이름·그래프 경로·이미지 파일 이름)을 지정한다.
- 마지막에 모든 방식의 결과 파일을 모아 비교표를 만드는 종합 프롬프트를 둔다. 행 수와 결과 파일 수가 맞는지 확인한다.
- 로그인만 있는 참가자용 「간이판」(Claude Code가 원리를 재현)과 키가 있을 때의 「공식판」(공식 패키지·실제 API)을 나눈다. 공식판 장은 「선택」으로 표시한다.

## API 키와 비용

- 키는 프로젝트 폴더의 `.env`에만 둔다. 프롬프트에 「키 값은 화면과 파일 어디에도 출력하지 마세요」, `.gitignore`에 `.env` 추가를 넣는다.
- 첫 프롬프트는 연결 확인과 사용량 기록 파일(`usage/log.csv`) 만들기다. 이후 API 프롬프트는 호출마다 토큰을 기록하게 하고, 마지막에 사용량·예상 비용 정리 프롬프트를 둔다.
- 대량 작업에는 작은 모델, 답하기에는 중간 모델을 지정한다. 모델 이름은 확인한 것만 쓴다.
- 비용이 큰 단계(그래프 색인 등)는 「예상 호출 수를 알려 주고, 제가 『진행』이라고 답하면 실행해 주세요」로 승인 관문을 둔다.
- API 답변 프롬프트에는 출력 상한을 넉넉히 지정하고(예: `max_tokens` 8000) 「답이 잘리면(stop_reason이 max_tokens) 알려 주세요」를 넣는다. 전체 구조처럼 긴 답이 나오는 문항이 기준이다.
- 프롬프트 캐싱 실습은 「첫 문항에서 캐시 생성, 둘째 문항부터 캐시 읽기」를 완료 조건으로 둔다. 시험 실행에서 답이 잘려 다시 받을 때는 그 문항만 다시 실행해 캐시 기록이 흐려지지 않게 한다.
- 사용량 정리 프롬프트는 실습별·서비스별 토큰 합계, 공식 가격표로 확인한 단가와 예상 비용, 캐시 절감액 한 줄, 「Claude Code 자체 사용량은 기록되지 않음」 안내를 담는다. 단가는 공식 가격 페이지에서 확인한 값만 쓰고 확인일을 적는다.

## 공식 도구와 외부 환경

- 「설치된 버전의 사용법(설정 형식·함수 이름)을 먼저 확인하고 그에 맞춰 주세요」를 넣는다. 공식 도구는 버전마다 사용법이 바뀐다.
- 시험 실행에서 기본 설정이 실패하면 필요한 설정을 프롬프트에 직접 적고 이유를 괄호로 단다(예: PageIndex 색인은 `mode="standard"`, 목차 없는 문서에서 기본 모드가 「no layout structure」 오류를 냄). 「막히면 멈춤」 지시만 두면 참가자가 그 단계에서 멈춘다.
- 최신 모델 응답의 첫 블록이 생각 블록일 수 있으므로, 스크립트는 응답에서 텍스트 블록만 골라 읽게 한다.
- 막힐 수 있는 설치(Ollama, ffmpeg, 영상 내려받기)는 「막히면 멈추고 알려 주세요」와 대체 경로(강사 배포 파일)를 둔다.
- Colab처럼 사람이 직접 할 단계는 프롬프트 사이에 번호 목록 「사람이 할 일」로 분리한다.
- 공개 모델 파인튜닝은 Colab 무료 GPU + 4비트 QLoRA + GGUF 내보내기 + 로컬 Ollama 질의의 흐름으로 쓰고, 학습 전·후·기준선을 비교하게 한다.
- 영상·저작물 내려받기는 실습 목적의 개인 열람 범위라고 주의 상자에 적는다.

## 금지

- 프롬프트 안에도 시간·분량 표기를 넣지 않는다(기술 값은 예외).
- 한 번 배포한 프롬프트 id와 문구를 다음 버전에서 이유 없이 바꾸지 않는다. 바꾸면 원고와 로그에 적는다.
