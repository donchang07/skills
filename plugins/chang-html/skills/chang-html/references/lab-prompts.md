# 실습 프롬프트 작성 규칙

참가자가 Claude Code에 붙여 넣는 모든 지시를 복사 버튼 상자로 만든다. 원고에서 메인이 전문을 쓴다.

## 기본 형식

```
{작업 위치}에서 작업해 주세요.
1. …
2. …
3. 결과는 {결과 파일 경로}로 저장해 주세요.

[완료 조건]
- {파일·개수·형식처럼 눈으로 확인할 수 있는 조건}
```

- 한 프롬프트는 한 결과 파일을 만든다. 결과 파일 경로를 반드시 적는다.
- 완료 조건은 참가자가 결과를 보고 직접 대조할 수 있는 문장으로 쓴다(「8개 답과 근거 문장이 있다」).
- 원문에 없으면 「원문에 없음」, 검색에 없으면 「검색된 조각에 없음」처럼 없을 때의 답을 지정한다. 지어낸 답을 가려내는 문항(예: 원문에 없는 가격)을 연습문제에 하나 넣는다.

## 방식별 짝: 만드는 프롬프트 + 질문 스크립트

- 기술·방식을 소개하는 장에는 방식마다 「만드는 프롬프트」(준비·색인·데이터 만들기)와 「질문 스크립트」(같은 연습문제로 묻고 근거 남기기)를 짝으로 둔다. 소개만 하고 만드는 법이 없으면 결함이다.
- 질문 스크립트는 그 방식의 강약이 드러나는 문항을 고르고(예: 흩어진 사실, 근거 없음), 근거 표시 방법(원문 문장·조각 번호·페이지 이름·그래프 경로·이미지 파일 이름)을 지정한다.
- 마지막에 모든 방식의 결과 파일을 모아 비교표를 만드는 종합 프롬프트를 둔다. 행 수와 결과 파일 수가 맞는지 확인한다.
- 로그인만 있는 참가자용 「간이판」(Claude Code가 원리를 재현)과 키가 있을 때의 「공식판」(공식 패키지·실제 API)을 나눈다. 공식판 장은 「선택」으로 표시한다.

## API 키와 비용

- 키는 프로젝트 폴더의 `.env`에만 둔다. 프롬프트에 「키 값은 화면과 파일 어디에도 출력하지 마세요」, `.gitignore`에 `.env` 추가를 넣는다.
- 첫 프롬프트는 연결 확인과 사용량 기록 파일(`usage/log.csv`) 만들기다. 이후 API 프롬프트는 호출마다 토큰을 기록하게 하고, 마지막에 사용량·예상 비용 정리 프롬프트를 둔다.
- 대량 작업에는 작은 모델, 답하기에는 중간 모델을 지정한다. 모델 이름은 확인한 것만 쓴다.
- 비용이 큰 단계(그래프 색인 등)는 「예상 호출 수를 알려 주고, 제가 『진행』이라고 답하면 실행해 주세요」로 승인 관문을 둔다.

## 공식 도구와 외부 환경

- 「설치된 버전의 사용법(설정 형식·함수 이름)을 먼저 확인하고 그에 맞춰 주세요」를 넣는다. 공식 도구는 버전마다 사용법이 바뀐다.
- 막힐 수 있는 설치(Ollama, ffmpeg, 영상 내려받기)는 「막히면 멈추고 알려 주세요」와 대체 경로(강사 배포 파일)를 둔다.
- Colab처럼 사람이 직접 할 단계는 프롬프트 사이에 번호 목록 「사람이 할 일」로 분리한다.
- 공개 모델 파인튜닝은 Colab 무료 GPU + 4비트 QLoRA + GGUF 내보내기 + 로컬 Ollama 질의의 흐름으로 쓰고, 학습 전·후·기준선을 비교하게 한다.
- 영상·저작물 내려받기는 실습 목적의 개인 열람 범위라고 주의 상자에 적는다.

## 금지

- 프롬프트 안에도 시간·분량 표기를 넣지 않는다(기술 값은 예외).
- 한 번 배포한 프롬프트 id와 문구를 다음 버전에서 이유 없이 바꾸지 않는다. 바꾸면 원고와 로그에 적는다.
