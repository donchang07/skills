# 작업 규모에 맞춘 협업

## Codex와 Claude Code

공통 내용·브랜드·검증 계약은 두 환경에서 동일하다. Codex에서는 `$chang-ppt`, Claude Code 개인 스킬에서는 `/chang-ppt`, Claude 플러그인에서는 `/chang-ppt:chang-ppt`로 호출한다. 현재 환경에 제공된 역할·위임 도구만 사용한다. Claude Code에서는 `.codex/agents/*.toml`이 자동 로딩된다고 가정하지 말고 역할 설명을 현재 제공되는 서브에이전트에 전달한다. Codex 전용 harness CLI나 native ID 등록을 Claude Code에서 강제하지 않는다. harness가 없으면 작업 명세·소유권·검증 결과를 프로젝트 작업 폴더에 기록하고 같은 역할 계약으로 실행한다. 위임 도구가 없으면 순차 실행하며 병렬 실행했다고 보고하지 않는다.

전체 개편, 독립 역할별 병렬 작업 또는 부분 재실행 때 읽는다. 프로젝트에 harness가 있으면 프로젝트 루트 `.agents/skills/harness/SKILL.md`와 그 runtime-guide.md를 읽는다. 이 스킬의 설치 폴더를 대상 프로젝트로 오인하지 않는다.

## 역할과 실행 범위

- 신규 제작: 조사·근거 정리 → 전체 스토리·장별 명세 → 제작 → 독립 QA.
- 기존 PPT의 전체 개편: 원본 진단과 내용 조사를 병렬 수행하고 설계에서 통합한 뒤 구현한다. 완성 구간의 QA는 독립적으로 병렬화할 수 있다.
- 정렬·서식 같은 작은 변경: 관련 규칙을 읽고 수정·QA만 수행한다. 매번 전체 조사나 새 하네스를 만들지 않는다.
- 스킬 자체 개선: 지침·참조·도구·트리거 및 설치본의 영향 범위를 대조하고 필요한 항목만 수정한다.

조사자는 근거와 불확실성, 설계자는 명세와 완료 기준, 구현자는 배정된 파일 편집, QA는 독립 검증과 오류 보고를 맡는다. QA가 제품 수정까지 겸하지 않는다. 부모가 공용 계약·통합·최종 판정을 소유한다. PPT·스킬·템플릿의 쓰기 소유권은 최신 작업 패킷에 명시한다.

## 하네스가 있는 프로젝트

실제 런타임 가이드의 init → 실제 ID 등록/start → 도구로 작업 배정 → 최종 결과 등록 → 실제 유휴 상태 기록 절차를 따른다. 역할 TOML은 현재 프로젝트 `.codex/agents/`에서 읽고, 현재 세션에서 역할이 발견되지 않으면 기본 에이전트에 해당 정의를 전달한 대체 실행을 기록한다. 독립 작업만 병렬로 수행하고 같은 PPTX를 두 작업자가 동시에 쓰지 않는다. 여러 작업자는 장별 명세·독립 파일을 만들고 부모가 통합한다.

각 패킷에는 프로젝트 루트, target_mode, 원본·기준 지문, 확정된 결정, 스킬 경로, 의존성, 쓰기 경로, 산출물, 완료 기준을 넣는다. 중요한 발견과 인계는 실제 메시지 전달과 로컬 기록을 구분한다. 사용자의 기존 승인 범위 안에서 진행하며 형식적 승인 대기를 추가하지 않는다.

## 부분 재실행과 완료

후속 변경은 기존 실행을 덮어쓰지 않고 새 run 또는 resume으로 남긴다. 입력·계약·출력 지문과 관련 의존성이 같을 때만 이전 결과를 재사용한다. 변경한 장은 다시 렌더링하고, 마스터·글꼴·공통 배치 변경은 영향을 받는 전체 장을 다시 확인한다. 변경하지 않은 PNG를 재사용하려면 해당 슬라이드·마스터·레이아웃·글꼴·렌더 환경이 동일하다는 근거가 있어야 한다.

일시적 도구 오류는 원인을 확인한 뒤 기본 1회 재시도한다. 수정·재검증은 기본 2회 후 원인과 남은 실패를 명시한다. 반복 한도에 도달했다고 실패를 통과로 바꾸지 않는다.

최종 PPTX 저장 → 렌더 → QA 보고서 확정 → manifest 작성 → 하네스 결과 등록 순으로 완료한다. manifest에는 원본/결과 raw SHA-256, 하네스 입력 digest(별도 필드), 기준 스킬 지문, 렌더러·글꼴·크기, 실제 확인한 슬라이드 ID와 담당자, 통과/실패/not_run을 기록한다. 보고서를 나중에 수정하면 지문을 다시 계산하고 결과를 다시 등록한다. 실제 확인하지 않은 렌더링이나 PowerPoint 동작을 통과라고 하지 않는다.
